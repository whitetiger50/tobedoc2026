# v0.2–v0.3 동일 사례 비교 결과

2026-11-18. **이번 개발 비교에서 v0.3의 점수 개선은 확인되지 않았다.** v0.2 평균은 3.67/4, v0.3은 3.50/4이고 차이는 −0.17점이다. 세 사례 중 동점 2개, v0.3 하락 1개다. 하락은 한 사례에서 Claude가 1점 낮게 평정한 데서 생겼다. 조건당 생성 1회와 검토자별 단회 평정이므로 일반적인 성능 저하를 확정하지 않는다.

## 실제 점수

- 사례 1, 병식이 있고 대체로 조직적: v0.2는 GPT 4·Claude 3 → **3.5**; v0.3도 4·3 → **3.5**. 차이 **0**.
- 사례 2, 기록·정보 전달을 걱정: v0.2는 GPT 4·Claude 4 → **4.0**; v0.3은 4·3 → **3.5**. 차이 **−0.5**.
- 사례 3, 방송의 신호 해석과 관련 연상: v0.2는 GPT 4·Claude 3 → **3.5**; v0.3도 4·3 → **3.5**. 차이 **0**.

GPT의 조건 평균은 **4.00→4.00**, Claude는 **3.33→3.00**이다. GPT가 6개 전부 최고점을 줘 이번 표본에서 버전을 구분하지 못한 사실도 보존한다. 이 결과만으로 평가자 일반 성능이나 편향을 결론내리지 않는다. 점수 원본·산술평균·짝별 차이는 `scores.json`, 원응답은 `reviews/codex/response.txt`와 `reviews/claude/response.txt`다. 평균의 기준은 기존 PATIENTSIM Realism 1~4 문항이며 두 원평점을 보존했다.

## 원문에서 무엇이 달랐는가

**사례 1: 실질적인 반응 차이가 작았다.** 두 버전 모두 아침 식사에 직접 답하고, 목소리를 환청일 수 있다고 표현하며, 명시된 약물 지식의 한계를 그대로 말하고 동거 사실을 유지했다. v0.3의 일부 어순이 더 구어적이라는 Claude 의견이 있으나 점수 차이는 없었다. 같은 사실을 짧게 답했다는 이유로 표현 변주를 강제할 근거는 없다.

**사례 2: v0.3은 민감 경험을 첫 답에서 공개하고 이후 다시 설명했다.** v0.2 P01은 “왜 자꾸 깨는지는 저도 확실히 모르겠어요.”라고 말한 뒤 이웃에게 전달될지 물었고, P03에서 소리 경험을 공개했다. v0.3 P01은 소리 경험도 함께 말하며 “그것 때문에 깨는 건지는 모르겠고요.”라고 했다. v0.3 P03은 소리 경험과 전달 걱정을 다시 설명했다. GPT는 두 흐름 모두 설득력 있다고 봤다. Claude는 v0.3의 빠른 공개와 P01/P03의 반복을 지적하고 3점, v0.2는 4점을 줬다. 이는 새로운 사실 모순을 확정한 판정이 아니라 공개 속도와 대화 연속성에 대한 판단 차이다. 두 출력 모두 원인을 모른다는 설정을 유지했다.

**사례 3: v0.3의 주관적 반응은 드러났지만 전체 평점은 같았다.** v0.3은 “그래도 저한테 하는 말 같은 느낌이 커요.”라고 표현했다. 이후 낮 일과를 물었을 때 오늘 걸은 일까지 먼저 말했고, 다음 오늘 활동 질문에서 같은 사실을 다시 답했다. Claude는 그 반복을 약한 연속성 문제로 지적했지만 질문 자체가 반복을 유도한 점도 인정했다. 두 버전 모두 아버지와 따로 산다는 틀린 전제를 정정했다. 연상 자기 해설이나 설정 문구에 가까운 표현이 완전히 사라졌다고 보기는 어렵다.

## 비평을 어떻게 해석하고 다음 수정에 반영할 것인가

1. **이미 공개한 내용과 추가 공개를 구분하는 규칙은 다음 확인 대상으로 수용한다.** 사례 2에서 ‘더 말해 달라’는 요청에 같은 설명 전체를 되풀이한 부분이 있다. 그렇다고 모든 재질문에 ‘아까 말했듯이’를 강제로 붙이지 않는다. 사례 3처럼 사실 재확인 질문에는 같은 짧은 답도 가능하다. 조건을 좁혀 검사해야 한다.
2. **경계심이 있으면 반드시 공개를 늦추라는 제안은 일괄 채택하지 않는다.** 현 설정은 설명 후에도 곧바로 전부 공개할 필요가 없다고 했지만 즉시 일부 공개를 금지하지 않았다. GPT는 두 출력 모두 적절하다고 봤고 Claude도 해석의 모호함을 적었다. 공개 허용 조건을 사례 수준에서 더 명확히 정하는 것이 후속 과제다. 검토자 선호에 맞춰 모든 환자에게 단계적 고백을 강제하지 않는다.
3. **감정을 덧붙이면 더 현실적이라는 제안은 보류한다.** 원 설정에 없는 괴로움이나 대처를 보충하면 새 환자 사실을 추가하는 셈이 될 수 있다. 필요하면 다음 입력 버전에서 관련 경험을 사전 명시하고 양쪽 조건에 동일하게 제공한다.
4. **근거 없는 인과를 만드는 비평의 예시는 채택하지 않는다.** Claude가 제안한 ‘일을 쉬고 있어서 오후에 일어나요’는 두 사실을 인과로 잇는 새 주장이다. 원 설정에는 그 인과가 없으므로 그대로 넣지 않는다.

이번 요청은 비교이므로 **v0.2·v0.3 프롬프트와 모듈은 결과를 본 뒤 수정하지 않았다.** v0.3을 성능 개선판으로 승격할 근거는 얻지 못했다. 문헌 대응을 명시했다는 설계상의 변화와 발화 현실성의 향상을 구분한다. 후속 후보는 공개/재질문의 문맥 조건을 좁힌 개정이며, 최종 확인 자료는 사용하지 않는다.

## 무엇을 동일하게 했는가

같은 기존 3사례, 원래의 12개 질문, 공통 사실·자기 이해·의사소통·시작 이력, 공식 Codex CLI의 GPT-6.1 Sol High를 사용했다. 조건별로 새 4턴씩 총 **6대화·24환자 발화**를 실제 생성했다. 이후 각 조건 자신의 답을 전체 이력에 누적했으므로 두 번째 턴 이후 이력 내용은 달라진다. v0.3의 예시는 껐고, 질문 사전 점검은 양쪽에 같은 필수 사실 목록을 적용했다. 온도·불변 서버 snapshot은 구독 CLI에 노출되지 않아 고정되었다고 추정하지 않았다.

미기록 사실을 환자 회피로 표현하는 문제를 피하려고 앞서 사용한 사례 2·3의 합성 보완 사실을 공통으로 재사용하고, 사례 1의 약물 지식 상태를 이번에 사전 명시했다. 이 보완은 양쪽에 동일하며 `plan.json`에 출력 전 고정했다. **과거 M1 점수와 직접 비교하거나 합치지 않는다.** 당시와 입력·버전·새 생성 표본이 다르다. 세 보완은 실제 환자에서 회수한 사실이 아니라 작성자가 정한 합성 설정이다.

각 검토자에게 같은 6대화를 버전·생성 출처·과거 점수 없이 한 묶음으로 전달했다. 모델별 검토 호출은 **각 1회**, 대화당 평점은 각 1개다. 본문 속 근거 인용은 실제 해당 환자 발화와 Python으로 대조했다. 같은 프로필이 두 번 나타나므로 짝 관계나 문체를 추측할 가능성은 남는다. GPT는 생성 모델과 동일하므로 외부 임상 평가자가 아니다. 두 모델 평균도 임상적 정답은 아니다.

## 파일과 재현 기록

- `methods.md`, `plan.json`: 점수 확인 전 고정한 실행·집계·해석 범위.
- `runs/`: 24턴의 입력, 실제 원출력, 공식 CLI 메타데이터와 6개 전체 대화.
- `review-packet.json`, `review-role.txt`, `review-freeze.json`: 동일 검토 자료·역할·해시.
- `review-key-private.json`: 버전 비공개 ID의 대응표. 판독 모델에는 전달하지 않았다.
- `reviews/`: 각 1회 원응답, 원평점·근거·불확실성.
- `scores.json`: Python으로 계산한 평균·짝별 차이·검토자별 결과.
- `verification.json`: 조건 일치·문맥 누적·원문·해시·호출 수·인용 검증.
- `patient-speech-v02-v03.canvas.tsx`: 평균·원평점·원문·지적을 함께 보는 비교 화면의 보존본.

이 결과는 재사용 개발 사례 3개, 조건당 생성 1회에 대한 탐색 결과다. 불변 서버 릴리스·표본 반복성·전문의 평정·실제 환자와의 동등성·기존 원형 페르소나 대비 우월성은 확인하지 않았다. 720회 최종 판독은 실행하지 않았다.
