# M3 비교 실행 명세

2026-11-18. 3개의 기존 합성 개발 사례에서 v0.2와 v0.3을 비교한다. 최종 확인 표본·실제 환자 자료·임상 검증이 아니다. 이 명세와 `plan.json`은 판독 점수를 보기 전에 작성했다.

- 조건: `schizophrenia-speech-m1-v0.2`와 `schizophrenia-speech-m2-v0.3`. 프롬프트와 코드·출처 대응 파일의 해시는 출력 전에 고정했다. 이번 비교 중에는 모듈을 수정하지 않는다.
- 생성: 공식 Codex CLI, 기존 ChatGPT 구독, `gpt-6.1-sol`, reasoning effort `high`. temperature와 불변 서버 snapshot은 구독 CLI에 노출되지 않아 추정하지 않는다. 조건당 사례별 한 대화, 대화당 새 환자 발화 4개로 총 6대화·24발화다. 원문을 보고 선택하거나 다시 생성하지 않는다.
- 입력: 환자 사실·자기 이해·의사소통 설정·질문 4개·시작 문맥은 두 조건에 동일하게 제공한다. v0.3의 표현 예시는 비활성이다. v0.3의 질문 검토 확인은 실제 설정 검토 후 기록하며 v0.2에도 같은 필수 사실 목록을 점검한다. 이 확인 표지는 생성 모델에 추가 정보로 전달되지 않는다.
- 설정 완결성: 사례 2의 ‘밤에 깨는 원인과 소리의 관계는 본인도 확실히 모름’, 사례 3의 ‘오늘 오후 집 근처를 걸음’은 앞선 v0.2 기능 확인 전에 작성했던 합성 사실을 재사용한다. 사례 1에는 ‘현재 약 이름·용량을 정확히 알지 못함’이라는 가상 지식 상태를 이번 출력 전에 추가한다. 새 약 이름·용량은 만들지 않는다. 세 보완 모두 두 조건에 똑같이 적용했다. 과거 원 설정 파일을 덮어쓰지 않는다.
- 문맥: 시작 이력은 동일하다. 이후에는 각 조건 자신의 실제 환자 답변을 그 조건의 전체 이력에 누적한다. 따라서 두 번째 턴부터 이력 텍스트는 달라질 수 있다. 이는 각 프롬프트를 적용한 전체 면담의 비교이며, 모든 턴에 동일 환자 답을 강제로 재생하는 비교는 아니다.
- 실행 순서: 사례 1·3은 v0.2 먼저, 사례 2는 v0.3 먼저다. 세 사례는 병렬 실행하며 각 사례 내 두 조건은 순차로 실행한다. 순서는 `plan.json`에 고정했다.
- 판독: GPT-6.1 Sol High와 Claude Opus 5.5가 같은 묶음을 각각 한 번 받아 여섯 대화를 각각 한 번 평정한다. PATIENTSIM Realism_w_Profile 원 1~4 앵커에서 ED patient를 psychiatric patient로 바꾼 기존 문항을 그대로 사용한다. 원 파일 해시를 확인한다. 생성 모델·버전명·프롬프트·과거 점수·상대 검토자의 답은 제공하지 않는다. 동일 프로필이 두 번 나타나므로 짝 관계나 문체로 조건을 추측할 가능성까지 제거한 완전 맹검은 아니다.
- 집계: 대화마다 두 원평점의 산술평균을 구한다. 사례별로 v0.3−v0.2를 계산하고 세 사례를 같은 비중으로 평균한다. 두 모델 각각의 조건 평균·차이도 보존한다. 원평점은 정수 1~4이고 평균의 .5를 보존한다. 누락값을 대체하지 않는다.
- 해석: 평균 차이와 원문 지적을 함께 본다. 점수 방향의 일치·불일치, 새로 나타난 사실 오류·회피·기계적 표현을 검토한다. 개발 사례 3개와 조건당 생성 1회이므로 통계적 유의성, 반복 안정성, 일반적 우월성이나 임상 타당성을 주장하지 않는다. 같은 모델이 생성과 판독을 맡는 GPT 자기 평가의 한계도 남는다.
- 이번 12개의 발화 평정(6대화×2모델)은 최종 720회 판독과 별도다. 이전 M1의 3.17점을 대조군으로 쓰거나 이번 자료와 합치지 않는다.

원시 자료는 `runs/`, 검토 입력과 버전 대응표는 `review-packet.json`과 `review-key-private.json`, 각 1회 검토는 `reviews/`, Python 집계는 `scores.json`에 보존한다. 결과가 나오기 전에는 이 파일에 결론을 추가하지 않는다.
