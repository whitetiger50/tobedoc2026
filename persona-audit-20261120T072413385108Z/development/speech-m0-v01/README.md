# M0 최소 발화 프롬프트 모듈

> 이 문서는 M0 준비 시점의 기록이다. 이후 실제 3대화·12발화 생성, 두 모델 단회 검토, v0.2 수정과 3발화 기능 확인까지 진행했다. 최신 실행 기록과 한계는 `../speech-m1-v01/README.md`를 읽는다. 아래 ‘생성 미실시’는 M0 당시 상태다.

> 최신 운영 변경(2026-11-18): 다음 개발 검토부터 GPT-6.1 Sol High·Claude Opus 5.5가 같은 묶음을 각각 1회 검토하고, 실제 발화의 수치 평정은 두 값의 산술평균으로 반영한다. 설계/코드의 무점수 비평은 서술형으로 종합한다. 720회 판독은 최종 결과 단계로 이연한다. `../../collaboration/development-review-policy.md`를 따른다. 기존 M0의 무점수 비평을 평점으로 소급 변환하지 않는다.

2026-11-18. 이 폴더는 **새로 작성한 합성 개발 자료**다. 실제 환자, 전문의 인증 사례, 평가자 파일럿 12개 프로필, 최종 확인 자료가 아니다. 입력의 면담 이력도 Codex가 작성한 설계 예시이며 실제 모델 응답이 아니다. Claude는 구현 전 M0 설계 요청만 검토했고 이 사례나 구현은 아직 검토하지 않았다.

`speech_module`은 입력 세 묶음(환자 설정, 의사소통 설정, 전체 면담 이력 및 현재 질문)을 검증해 기존 LLM에 적용할 메시지를 만든다. Python 표준 라이브러리만 사용한다. `generate(data, backend, directory)`는 명시적으로 제공된 전송 함수를 **한 번** 호출하고 환자 텍스트만 반환한다. 기본 제공 API·모델·자동 재시도는 없다. 현재 구독 세션의 수동 사용을 위한 `prepare`/`import` 경로도 있다.

## 지금 확인한 것과 확인하지 않은 것

세 입력의 구조, 전체 이력 보존, 분할 표지, 해시 재현, 전달 함수 호출 및 기록·실패·덮어쓰기 방지를 구조 테스트로 확인한다. 이 테스트는 모의 전송 함수와 임시 파일을 쓰며 환자다운 발화 생성·설정 준수·프롬프트 주입 방어·현실성을 입증하지 않는다. 프롬프트에 지시가 있다는 사실과 LLM이 지켰다는 사실을 구분한다. 문장 수나 증상 단어 수로 현실성을 자동 판정하지 않는다.

실제 생성 모델/버전/추론 설정은 아직 동결하지 않았다. 환자 발화 생성, 임상 검증, B/T 성능 비교, 48대화·720회 판독은 이 단계에서 수행하지 않았다. `prepared/`는 실행 결과가 아닌 입력 패킷이다. `probes.json`은 다음 원문 확인 질문이며 합격 점수나 관측 결과가 아니다.

## 사용

프로젝트 루트에서 새 폴더로 준비한다. 이미 있는 실행 폴더는 덮어쓰지 않는다.

```bash
python3 -m speech_module prepare --input development/speech-m0-v01/inputs/DEV-M0-01.json --out /tmp/speech-m0-example-new
python3 -m unittest discover -s tests -p 'test_speech_module.py' -v
```

준비는 추론을 호출하지 않는다. `packet.json`의 system/user 메시지를 허가된 구독 세션에 전달해 실제로 받은 답변을 별도 JSON에 보존한 후 가져올 수 있다. 자동으로 다른 구독 모델을 호출하지 않는다. 수동 전달은 원문 그대로 옮겼다는 사용자 기록이며 도구로 전송 일치를 독립 검증한 것은 아니다.

응답 JSON 필드는 `text`, `model_id`, `model_version`, `settings`, `execution_mode`, `provenance`다. `text`는 받은 원문, `execution_mode`는 수동 구독 실행일 때 `manual_subscription`이다. 실제 확인 가능한 모델 ID와 버전을 기록한다. 정확한 버전이나 설정을 제공하지 않는 UI라면 `unavailable_in_subscription_ui`처럼 미확인임을 명시하며 추정값을 채우지 않는다. 이 경우 정식 비교 실행의 동결 요건 충족 여부를 별도 결정해야 한다. `settings`에는 확인된 제어값과 확인 불가능한 항목을 함께 기록한다. `provenance`에는 실제 세션/출력 파일의 출처를 적고 자격 증명은 넣지 않는다.

```bash
python3 -m speech_module import --run-dir /tmp/speech-m0-example-new --response /absolute/path/to/actual-response.json
```

전송 함수 연동 시 `generate`에 callable을 전달한다. callable은 `messages` 전체를 받아 위와 같은 응답 dict를 반환하고 `execution_mode=injected_backend`를 기록한다. 이 모듈에 유료 API 호출 구현을 추가하지 않았다. 시험용 함수는 반드시 `test_fixture`로 표시한다. 테스트 출력은 `fixture_only`, 실제 응답 기록은 `response_recorded_unrated`로 분리한다. 후자는 임상적 판정이 아니다. 반환값은 환자 텍스트이며 메타데이터·원문은 실행 폴더에 남는다.

## 입력과 상태 원칙

- `patient.facts`는 고유 ID, 사실 종류, 원문 내용, 환자의 인지 여부, 공개 정책을 갖는다. 주관적 경험/믿음은 객관적으로 확인된 생활·치료 사실과 다른 종류다. `self_understanding`에는 병식과 귀인을 사례 문장으로 적는다.
- `communication`은 조직성·자발성·경계심·표현량의 네 서술이다. 수치나 어휘 빈도로 증상을 강제하지 않는다.
- `history`는 완결된 면담자→환자 쌍 전체다. 현재 질문은 `current_question`으로 한 번만 제공한다. 이력을 요약하거나 자르지 않는다. 새 턴에는 실제 답변을 history에 추가해 새 실행 폴더를 만든다. 문맥 한계가 있으면 전송 구현에서 실패를 드러내고 임의로 자르지 않아야 한다.
- 분할은 기본 `development`만 허용한다. 다른 단계는 `expected_partition`/`--partition`을 명시해야 한다. 이 표지는 우발적인 혼용을 줄이는 장치이며 사람이 내용을 본 사실까지 추적하는 접근 통제는 아니다. 개발에 노출한 사례는 분할 이름을 바꿔도 미사용 확인 자료가 되지 않는다.
- JSON 구조만 자동 검증한다. 내용의 임상 정합성은 `case-author-checks.json`의 작성자 점검과 다음 원문 검토 과제다. 작성자 점검은 임상의 인증이 아니다.

## 비교 범위와 다음 작업

현재는 T 모듈만 구현했다. B의 원형 소스·프롬프트·입력 위치를 확인한 후 동일한 사실/의사소통/전체 이력/질문을 전달할 수 있는지 결정한다. 임의의 약한 B는 만들지 않는다. 공통 정보와 프롬프트 구조 효과를 분리할 필요가 있으면 정보량 일치 보조 조건을 실행 전에 기록한다. 확인 세트·질문·프롬프트·모델/설정 해시는 확인 발화를 보기 전에 동결한다.

다음 단계는 같은 생성 모델에서 세 개발 사례의 `probes.json` 질문을 실제로 실행하고 원문을 읽는 것이다. 질문 순서와 설명·재질문을 포함하되 고정 사실/공개/역할 유지가 어떻게 나타나는지 기록한다. 원문이 확보된 뒤에만 작은 M1 검토 묶음을 작성한다. M0 검토를 억지로 반복하지 않는다. 실제 판독과 임상 타당성은 기존 파일럿 계획의 별도 절차다.
