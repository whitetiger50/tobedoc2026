# M6 생성 변동성 점검 — 생성·평정 전 고정

사용자 요청: 같은 개발 사례 3개에서 환자 설정·질문·생성 모델을 유지하고 v0.2/v0.4를 각각 3회 생성한다. 두 평가 모델이 각각 1회 검토하고 생성 변동성·정보 공개·반복 흐름을 비교한다. 환자 프롬프트는 수정하지 않는다.

## 생성 설계

- M4 `plan.json`의 `case_id`, `input`, `questions`, `required_fact_ids`를 그대로 복사한다. 새 사실·질문·예시를 넣지 않는다. v0.2와 v0.4의 프롬프트·소스 맵·모듈 구현을 해시로 고정한다.
- 3사례 × 2버전 × 3회 = **18개 새 대화**, 대화마다 환자 4턴, 합계 **72개 새 환자 발화**를 생성한다. 과거 M4의 대화를 첫 반복으로 재활용하지 않는다.
- 생성 모델은 이전과 같은 공식 Codex CLI의 `gpt-6.1-sol`, reasoning effort `high`다. 기존 ChatGPT 구독을 사용한다. temperature·seed·불변 서버 스냅샷은 CLI에 노출되지 않아 같게 고정했다고 주장하지 않는다.
- 매 대화는 같은 작성 시작 이력에서 새로 시작한다. 이후 턴에는 그 대화의 실제 생성 답변만 누적한다. 다른 반복·버전의 생성물이나 평점은 전달하지 않는다. 전체 이력을 유지하고 요약·잘라내기를 하지 않는다.
- 사례별 worker 3개를 사용하며 각 사례 안에서는 반복마다 먼저 생성할 버전을 교대한다. 반복 번호는 실행 블록이지 두 버전에 공유된 난수 seed나 확률적으로 매칭된 쌍이 아니다.
- 질문당 실제 호출 1회, best-of·점수에 따른 재생성·응답 선택·wrapper 자동 재시도 없이 모두 보존한다. 기술 실패는 별도 기록하며 정상 발화로 채워 넣지 않는다. 18대화가 완료되어야 전체 비교를 집계한다.
- 기존 질문별 작성자 확인과 필수 사실 ID 검사를 유지하고 가상 예시 옵션은 비활성이다. 확인 플래그는 이번에 임상 검토를 새로 받았다는 뜻이 아니다.

## 두 모델의 단회 검토

18대화를 섞은 한 묶음을 GPT-6.1 Sol High·Claude Opus 5.5(medium effort, 이전과 동일)에 각각 새 세션 1회 제공한다. **판독 CLI 호출 2개·대화 평점 36개**다. 도구 없는 공식 구독 CLI, 새 임시 폴더·비영속 문맥을 사용하며 유료 API를 사용하지 않는다.

버전·생성 모델·반복 번호·이전 점수·다른 평가자 응답·프롬프트를 가린다. 같은 묶음과 역할을 두 모델에 제공한다. 프로필은 한 번씩 제시하고 대화가 `profile_ref`로 참조한다. 고정 seed로 순서를 섞고 같은 프로필을 연속 제시하지 않는다. 유사한 대화가 함께 있어 관련성을 알아볼 수 있으므로 완전 눈가림·대화별 완전 독립 제시로 해석하지 않는다. M5의 묶음 내 참조 한계를 숨기지 않는다.

수치 평점은 같은 PATIENTSIM Realism 1–4 앵커다. 생성된 환자 발화를 문맥 속에서 평가하고 작성 시작 이력 자체는 새 출력으로 채점하지 않는다. reason·실제 인용·issues·uncertainty를 보존한다. 추가로 각 대화의 다음 **서술형 관찰**을 받는다. 새 현실성 점수나 검증된 임상 척도를 만드는 것이 아니다.

- `disclosure_flow`: 생성된 턴 중 민감 경험/믿음이 처음 나온 턴(P01~P04/없음/불확실), 제한적 공개·일부 공개 후 추가 설명·초기 다수 정보 공개·기타·비해당·불확실의 기술 범주와 실제 원문 근거.
- `repetition_flow`: 짧은 재확인·관련 추가 설명·기계적 되풀이·혼합·반복 주제 없음·불확실의 기술 범주와 실제 원문 근거.
- 빠른 공개 자체·비슷한 질문에 대한 동일 사실 답변·해소되지 않은 우려의 재질문은 자동 오류가 아니다. 특정 문구나 공개 지연을 정답으로 요구하지 않는다.
- 사례 2에서는 최초 소리/관찰 믿음의 공개와 우려의 재제기, P03의 새 정보/기존 정보 연결에 집중한다. 사례 3에서는 일상/오늘 질문의 중복과 반복 답변, 미설정된 세부 구체화를 구분한다. 사례 1에서는 재확인에 대한 사실 일관성을 확인한다.

추가 관찰 과제가 이전 M4/M5의 판독 문맥과 다르므로 이전 점수와 직접 합치지 않는다. 전체 18개의 단회 평정과 흐름 관찰을 한 번에 요청하며 별도 설계 검토·추가 평정은 자동 실행하지 않는다. JSON 구조·점수 범위·누락/중복·근거 인용의 실제 존재·범주 값·최초 민감 턴 근거를 Python으로 확인한다. 형식 오류 시 원응답을 보존하고 누락을 추정하지 않는다.

## 사전 분석

1. 대화별 두 원평점의 산술평균을 보존한다. 사례×버전별 세 생성물에 대해 원평점·평균·최소/최대·범위·표본 SD를 제시한다. 버전 전체 평균은 세 사례에 같은 가중치를 준다. 평가자별 평균과 방향도 남긴다.
2. 같은 사례×버전 내 네 환자 답변 전체의 정확히 동일한 문자열 시퀀스 수와 환자 발화 문자 수의 범위를 계산한다. 이는 표면적 변동이며 의미적 다양성이나 현실성 점수가 아니다.
3. 공개·반복 범주는 평가자별·사례별·버전별 빈도를 제시하되 불확실/혼합도 그대로 보존한다. 두 모델의 해석이 다르면 임의 합의 라벨로 합치지 않는다. 직접 발화 인용과 원문으로 해석을 뒷받침한다.
4. 점수의 생성물 간 변동에는 생성 차이와 단회 평가의 변동이 모두 포함된다. 이를 생성 모형만의 분산으로 분해했다고 주장하지 않는다. M5는 다른 고정 대화·묶음이므로 분산 보정값으로 차감하지 않는다.
5. 18대화가 독립 환자 18명은 아니다. 같은 3개의 재사용 개발 프로필이므로 p값·CI·임상 타당성·최적화·동등성·일반적 우월성을 선언하지 않는다. 최종 미사용 사례나 720회 계획은 건드리지 않는다.

## 보존과 중지 경계

모든 입력·역할·모델 선택·명령·시각·원출력·환자 텍스트·세션 메타데이터·프로필/프롬프트/계획 해시를 보존한다. 점수를 보고 프롬프트를 고치지 않는다. 과거 파일 삭제·새 모델·새 패키지·별도 API·자격 증명 값 출력·로그인 변경은 하지 않는다.
