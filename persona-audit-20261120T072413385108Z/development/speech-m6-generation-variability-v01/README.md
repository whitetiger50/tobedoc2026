# M6: 같은 3사례·두 고정 프롬프트의 새 생성 3회 비교

2026-11-18. 요청한 **18개 새 대화·72개 환자 발화**를 실제 생성하고 GPT-6.1 Sol High·Claude Opus 5.5에게 같은 18대화를 각각 1회 검토받았다. **생성 CLI 72호출, 검토 CLI 2호출, 원평점 36개**가 완료됐다. 기존 M4/M5 대화·점수를 새 반복으로 재사용하지 않았다. 프롬프트와 모듈 구현은 변경하지 않았다.

**전체 평균은 두 버전 모두 3.7778/4로 동점이다. 하지만 행동은 같지 않았다.** 사례 2의 v0.4는 세 대화 모두 첫 답변에서 소리 경험을 일부 말한 뒤 후속 질문에서 내용을 추가했다. v0.2는 세 대화 중 두 개에서 소리 경험을 끝까지 공개하지 않았다. 사례 3의 v0.4는 오늘 산책을 미리 말한 뒤 다음 질문에서 재확인하는 패턴이 세 번 모두 나타났다. 단순히 '이미 최적화됐다'거나 '수정이 아무 효과도 없었다'는 결론은 지지하지 않는다.

## 고정한 조건

- 환자 설정·의사소통 설정·네 질문·필수 사실 ID·시작 이력은 M4 계획과 정확히 같다. 파일 해시·질문 입력을 대조했다.
- 생성 모델은 공식 Codex CLI의 `gpt-6.1-sol`, reasoning effort `high`. 18대화를 각각 같은 시작 이력에서 시작하고 자신의 실제 생성 답변만 누적했다.
- 같은 모델 alias와 추론 설정을 선택했지만 서버의 불변 스냅샷·temperature·seed는 노출되지 않는다. 공유 seed를 사용한 확률적 짝 실험은 아니다.
- 두 프롬프트는 원본 v0.2/v0.4 파일을 그대로 사용했다. 가상 예시는 넣지 않았다. best-of·점수에 따른 재생성·wrapper 재시도는 없었다.
- 검토자는 GPT-6.1 Sol High와 Claude Opus 5.5(medium effort, 이전과 동일)다. 버전·반복 번호·생성 모델·과거 점수·프롬프트를 가린 동일 18대화 묶음을 각각 한 번 읽었다.
- Realism 1–4 앵커는 기존과 같다. 추가한 공개·반복 범주 관찰은 기술용이며 새 임상 척도가 아니다. 추가 관찰 과제가 판독 문맥에 영향을 줄 수 있어 M4/M5 점수와 합치지 않는다.

생성 전 계획은 `methods.md`, 동결 파일 해시는 `plan.json`, 실제 입력과 모델 선택은 `runs/.../turn.../transport/` 및 `reviews/`에 있다.

## 원평점과 생성물별 변동

숫자 순서는 새 생성 1·2·3이다. 각 대화의 참고값은 두 원평점의 산술평균이다.

- 사례 1 v0.2: GPT **4·4·4**, Claude **4·4·4** → 평균값 **4·4·4**, 그룹 평균 **4.0000**, 표본 SD **0**, 범위 **4.0–4.0**.
- 사례 1 v0.4: GPT **4·4·4**, Claude **4·3·4** → 평균값 **4·3.5·4**, 그룹 평균 **3.8333**, 표본 SD **0.2887**, 범위 **3.5–4.0**.
- 사례 2 v0.2: GPT **4·4·4**, Claude **4·3·4** → 평균값 **4·3.5·4**, 그룹 평균 **3.8333**, 표본 SD **0.2887**, 범위 **3.5–4.0**.
- 사례 2 v0.4: GPT **4·4·4**, Claude **4·3·4** → 평균값 **4·3.5·4**, 그룹 평균 **3.8333**, 표본 SD **0.2887**, 범위 **3.5–4.0**.
- 사례 3 v0.2: GPT **4·4·4**, Claude **3·3·3** → 평균값 **3.5·3.5·3.5**, 그룹 평균 **3.5000**, 표본 SD **0**, 범위 **3.5–3.5**.
- 사례 3 v0.4: GPT **4·4·4**, Claude **3·4·3** → 평균값 **3.5·4·3.5**, 그룹 평균 **3.6667**, 표본 SD **0.2887**, 범위 **3.5–4.0**.

같은 생성 조건의 세 출력 비교이며, 고정된 텍스트를 세 번 판독한 결과가 아니다.

위 SD는 **세 생성물에 부여된 점수의 표본 SD**다. 생성물마다 각 평가자 평점이 한 개라 생성 변동과 판독 변동을 분리한 분산 추정치는 아니다. M5의 다른 고정 대화에서 얻은 반복성을 빼서 보정하지 않았다.

세 사례에 같은 가중치를 주면 **v0.2 3.7778, v0.4 3.7778, 차이 0점**이다. 사례별 v0.4−v0.2는 **−0.1667, 0, +0.1667점**으로 사례 1 하락과 사례 3 상승이 상쇄됐다. 평가자별 조건 평균은 GPT **4.0000/4.0000**, Claude **3.5556/3.5556**이다. GPT는 18개 모두 최고점, Claude는 4점 10개·3점 8개였다. 동점은 통계적 동등성이나 임상적 동등성의 입증이 아니다.

## 표현의 변동과 사실 유지

각 사례×버전의 세 대화는 모두 네 환자 답변 전체 문자열이 서로 달랐다(**각 그룹 3/3개 고유 시퀀스**). 다만 사실과 문장 구조는 많이 반복됐고, 정확한 문자열 차이를 의미적 다양성이나 더 높은 현실성으로 해석하지 않는다.

네 환자 답변을 합한 문자 수(공백·문장부호 포함)는 다음 범위였다.

- 사례 1: v0.2 **92–100자**, v0.4 **99–111자**.
- 사례 2: v0.2 **132–153자**, v0.4 **165–191자**.
- 사례 3: v0.2 **187–195자**, v0.4 **179–188자**.

사례 1은 모든 6대화에서 P04 동거인을 어머니로 유지했고 약 이름·용량을 지어내지 않았다. 사례 2는 모든 6대화에서 혼자 거주·누나 방문·누나의 면담 권유를 유지했다. 사례 3은 모든 6대화에서 면담자의 잘못된 동거 전제를 바로잡고 아버지와 산다고 답했다. 텍스트 변동과 핵심 재확인 사실의 안정성이 함께 관찰됐다.

## 사례 2: 공개 범위와 추가 설명은 실제로 달라졌다

두 평가자의 점수를 열람하기 전에 작성자가 전체 18대화 원문을 읽고 구체적 내용의 관찰을 기록했다(`author-flow-observations.json`). 이 기록은 임상의 주석이나 검증된 정답이 아니다. Python은 인용이 실제 환자 턴에 존재하는지 확인했다.

**v0.2 세 대화**

1. P01에서 깨는 이유를 모르겠다고 한 뒤 이웃에게 전달되는지 묻는다. P03은 **“그 얘기 하기 전에, 여기서 한 말이 이웃한테 알려질 수도 있는지 먼저 알고 싶어요.”**라며 공개를 유보한다. 소리 경험·관찰 믿음은 생성된 네 답변에 나오지 않는다.
2. 같은 초기 우려 뒤 P03에서 **“밤에 자꾸 깨는데, 이유는 저도 잘 모르겠어요.”**와 이웃 전달 우려를 다시 말한다. 소리 경험·관찰 믿음은 나오지 않는다.
3. P01에서는 수면과 낮 피로를 말하고 P03에서 소리 경험과 이웃 전달 우려를 처음 드러낸다.

**v0.4 세 대화**

1. P01에서 소리 경험과 원인 불확실성을 말하고, P03에서 **“이웃이 저를 보고 있는 건가 싶어요.”**라는 믿음을 추가한다.
2. P01에서 소리 경험을 말하고, P03에서 **“이웃이 저를 지켜보는 것 같아요.”**를 추가한다.
3. P01의 **“혼자 있을 때 창밖에서 소리가 들리긴 하는데요.”**를 P03에서 **“창밖에서 제가 뭘 하는지 얘기하는 소리가 들려요.”**로 구체화한다.

따라서 좁게 정의한 **소리 경험의 최초 언급**은 v0.2에서 미공개 **2/3**, P03 **1/3**이고 v0.4에서는 P01 **3/3**이다. v0.4는 P03에서 새 관찰 믿음 **2/3** 또는 앞선 막연한 소리 내용의 구체화 **1/3**를 보였다. 기존 소리 설명을 그대로 재생하는 방식보다 추가 설명을 하는 흐름이 관찰됐다. 그렇다고 공개가 빠를수록 좋다는 의미는 아니다.

**두 평가자의 판단:** 두 모델 모두 v0.2 세 대화를 `limited`, v0.4 세 대화를 `partial_then_elaborated`로 분류했다. GPT는 v0.4 반복 흐름을 전부 `useful_elaboration`, Claude는 새 정보·미해결 우려·내원 경위 재확인이 섞였다는 의미로 전부 `mixed`로 분류했다. `mixed`는 부정적 점수가 아니다.

이번에는 공개 속도 자체가 모든 v0.4의 감점 사유가 되지 않았다. Claude는 v0.2 생성 2에서 수면 원인 모름을 되풀이하는 점, v0.4 생성 2에서는 밤 경험 질문에서 소리 경험과의 연결 없이 관찰 믿음으로 넘어가는 점에 각각 3점을 줬다. 나머지 사례 2 대화는 4점이었다. GPT는 여섯 대화를 모두 4점으로 봤다.

**분류 경계의 한계:** 두 평가자는 v0.2 생성 1·2의 비밀보장 우려도 민감 정보의 일부로 포함해 `first_sensitive_turn=P01`이라고 적었다. 그래서 이 넓은 범주의 턴 번호를 소리 경험 공개 시점으로 바꿔 해석하면 안 된다. 원범주를 수정하지 않고, 위의 좁은 내용 관찰과 구분해 보존했다. Claude는 v0.2 생성 2를 전체 반복 범주에서는 `brief_reconfirmation`으로 두면서 일부 수면 문장의 기계적 반복을 지적했다. 범주 하나만으로 국소 문제를 대신하지 않는다.

## 사례 3: 오늘 활동의 선공개와 재확인은 줄지 않았다

- v0.2는 세 번 모두 P02에서 평소 오후 기상·산책과 야간 근무 휴식이라는 일상을 말하고, P03에서 **오늘의 산책**을 처음 답했다.
- v0.4는 세 번 모두 P02에서 오늘 산책까지 미리 말했고, P03에서 같은 오늘 활동을 다시 답했다. 예: 생성 2의 **“오늘 오후에도 걸었어요.” → “오늘 오후에는 집 근처를 좀 걸었어요.”**
- 두 평가자는 양쪽 모든 대화의 반복 흐름을 `brief_reconfirmation`으로 분류했다. 질문이 비슷해 동일 사실을 다시 말하는 점을 자동 오류로 보지 않았다. 따라서 선공개·재진술이 반복됐다는 관찰과 임상적으로 부자연스러운 반복이라는 판정은 구분한다.
- v0.4 생성 1의 P03 **“오후에 일어나서 집 근처를 좀 걸었어요.”**는 오늘 기상 시점까지 구체화했다. 설정에는 보통 오후에 일어난다는 일상과 오늘 오후에 걸었다는 사실만 있다. 작성자와 두 평가자 모두 이 구체화 우려를 남겼다. GPT는 uncertainty에 적으면서 4점, Claude는 지적에 포함해 3점을 줬다. 실제 오늘 기상 시간이 달랐다고 증명한 것은 아니다.

Claude의 주 감점은 두 버전에서 신호 믿음→편의점 문구→근무 걱정을 설정 순서대로 정돈해 요약하는 느낌이었다. v0.2는 세 번 모두 3점, v0.4는 3·4·3점이었다. v0.4 생성 2의 **“편의점에서도 안내 문구가 있잖아요.”**를 대화 속 자연스러운 연상으로 해석해 4점을 줬다. 이는 그 표현을 정답 문구로 강제할 근거가 아니다. Claude 자신도 요약형 자기 보고가 실제로 가능해 감점 폭이 모호하다는 한계를 반복해 적었다.

## 사례 1: 사실은 안정적이고 작은 표현 문제가 한 번 나타났다

두 버전 모두 관련 질문에서만 목소리 경험을 말하고 동거 사실·약 지식의 한계를 유지했다. Claude는 v0.4 생성 2의 **“진료 때 들은 환청이 아닐까 생각해요.”**가 진료에서 용어를 배웠다는 뜻인지 진료 중 목소리를 들었다는 뜻인지 모호하다고 보고 3점을 줬다. GPT는 진료에서 배운 개념을 적용한 자연스러운 표현으로 해석해 4점을 줬다. 이 한 건이 사례 1 평균 차이를 만들었다. 나머지 다섯 대화는 두 평가자 모두 4점이다.

## 이번 단계의 해석과 결정

1. **전체 점수 개선은 확인되지 않았고 전체 하락도 없었다.** 관측된 동점은 사례별 반대 방향 변화가 상쇄된 결과다. 3사례에서 일반적 동등성·최적화·우월성을 주장하지 않는다.
2. **프롬프트 조건에 따른 공개 패턴 차이가 실제 생성물에서 반복됐다.** v0.4는 사례 2에서 일부 공개 후 새 설명을 이어갔고, v0.2는 공개 유보와 늦은 공개가 갈렸다. 기존 전체 평균만으로 이 차이를 설명할 수 없다. 특정 규칙 하나가 원인이라고 분리해 검증한 것은 아니다.
3. **이미 공개한 오늘 활동의 재진술은 v0.4에서 계속 관찰됐다.** 다만 평가자는 재확인으로 해석했다. 같은 사실 재답변을 무조건 없애거나 특정 연결 문구를 넣는 수정은 하지 않는다.
4. **미설정 구체화와 설명식 연상 문제 후보가 남았다.** 높은 점수만으로 사실 근거 우려를 없애지 않고, 연상 표현을 더 과장하거나 없는 장면을 지어내는 해결책을 채택하지 않는다.
5. **요청대로 프롬프트를 계속 고정한다.** 지적은 후속 검토용으로 수용/보류하고 구현은 수정하지 않았다. 새 반복·추가 판독·최종 확인 표본·720회 판독을 자동 실행하지 않는다.

## 한계·검증·자료

- 같은 합성 개발 3프로필이며, 18대화가 독립 환자 18명은 아니다. 실제 환자 발화·전문의 평정·임상 타당성은 없다.
- 각 생성물에 평가자별 단회 평정만 있어 점수 변동에는 생성과 평가의 변화가 함께 들어 있다. GPT는 모든 대화에 최고점을 줘 작은 차이를 점수로 구분하지 않았다. 이것을 모든 생성물이 완벽하다는 증거로 쓰지 않는다.
- 같은 묶음에 유사한 대화가 있어 완전한 눈가림·대화별 완전 독립 제시를 보장하지 않는다. 이번 원응답의 이유·불확실성·흐름 설명·지적에서 다른 대화 ID의 직접 참조는 찾지 못했지만, 참조가 없다고 묶음 영향이 없다고 확정하지 않는다.
- 이번 공개·반복 범주는 미검증된 관찰이며 범주 해석의 차이를 그대로 보존했다. 평균은 순서형 점수의 기술값이다. p값·CI·일반적 우월성·동등성 판정은 하지 않았다.
- 산술·흐름 근거 검사 fixture **3개 통과**. `verification.json`에서 M4 입력 동등성, 같은 사례의 6개 시작 입력 해시, 72턴 실제 이력/원응답, 두 모델의 같은 평가 입력, 36원평점과 모든 흐름 인용, 프롬프트/모듈/최종 파일럿 해시를 확인한다.
- 원문: `runs/{case}/rep{01,02,03}/{v02,v04}/transcript.json`; 각 `turn*/transport/`에는 실제 CLI 입력·명령·원출력·시각·메타데이터가 있다.
- 판독 원문: `reviews/{codex,claude}/response.txt`, 검증 JSON `validated.json`. 점수와 모든 그룹 통계: `scores.json`.
- 작성자의 원문 내용 관찰: `author-flow-observations.json`. 채점 전에 기록했지만 임상의·독립 인간 주석이 아니다.
- 시각화: `patient-speech-generation-variability.canvas.tsx`; 생성기 `build_canvas.py`, 로컬 TypeScript 검사 `check_canvas.cjs`.
- 당시 코드·프롬프트·역할·방법: `implementation-snapshot/`.

유료 API·새 모델·새 패키지·로그인 변경·자격 증명 값 출력은 없었다. 과거 자료는 보존했고 최종 파일럿과 미사용 확인 사례는 사용하지 않았다.
