# M2: 실제 생성 프롬프트 확인과 근거에 따른 v0.3

2026-11-18. 이번 단계는 생성 지시의 출처를 확인하고 기존 v0.2를 개정한 작업이다. 실제 환자 자료, 새 환자 발화, 새 현실성 평점, 전문가 검증은 추가하지 않았다. v0.1의 3.17/4점을 새 버전의 점수로 사용하지 않는다.

## 무엇을 실제로 확인했는가

**PSYCHE v1** — [원문](https://arxiv.org/html/2501.01594v1). Methods의 Simulated Patient에서 SP-Prompt-1/2/3의 구성과 추가 지시를 확인했다. 전체 환자 system prompt가 그대로 공개된 것으로 취급하지 않는다. PDF p.23 Figure 8과 p.24 Figure 9는 **의사 에이전트** 프롬프트다. p.38 Table 11에는 실제 사고과정 지시와 예문이 있지만 양극성장애의 사고비약을 대상으로 한다. 여기서 가져오는 것은 설정·표현 방법·예시를 분리해 제공하는 설계 방법이며, 예문의 사고 양상을 조현병에 이식하지 않는다. 고정 발화량과 의학용어 일괄 제한도 채택하지 않았다. v1의 주요 검증 질환에 조현병이 포함되지 않았다는 범위를 유지한다.

**PATIENT-Ψ** — [원저자의 실제 프롬프트 조립 함수](https://github.com/ruiyiw/patient-psi/blob/de72a768e5366d3e94f7d8c711c563fb4a5b4d26/app/api/getDataFromKV.ts), `formatPromptString`. 기존 고정 스냅샷을 해시 검증했다. 환자 이력·인지모형·상황·생각·감정·행동을 주고 인지모형 자체는 설명하지 않게 하는 실제 역할 지시가 있다. 프로필을 환자 말로 바꾸는 방법을 참고했다. CBT 배경, 이미 수주간 치료받았다는 전제, 대화에 따른 호전, 문장 수 제한, tangent 스타일의 주제로 돌아오지 않는 규칙은 가져오지 않았다.

**Roleplay-doh** — [원문·Appendix E](https://aclanthology.org/2024.emnlp-main.591.pdf). PDF p.15, 논문 p.10584의 E.2가 실제 다음 환자 답 생성 템플릿이다. 시나리오·환자 원칙·대화 이력을 사용한다. E.3의 문맥 적용성 확인을 v0.3의 조건부 지시 설계에 참고했다. 원 연구의 다단계 원칙 분해·판독·재작성 호출을 구현한 것은 아니다. 공개 부록과 Table 2까지만 사용했으며, gated 개별 전문가 원칙 자료는 확보하거나 우회하지 않았다.

**정신과 음성 프로토타입** — [본문](https://link.springer.com/article/10.1007/s40596-026-02422-9), [실제 Table 1](https://link.springer.com/article/10.1007/s40596-026-02422-9/tables/1). 조현병 포함 네 사례를 시험한 연구지만, 공개된 프롬프트 구조 예시는 **우울증용**이다. 배경·증상·역할·제약·교육 피드백을 분리한 내용은 확인했다. 확인한 공개 본문과 링크 목록에서는 조현병 전체 프롬프트나 별도 보충파일을 확보하지 못했다. 따라서 조현병 프롬프트를 재현했다고 주장하지 않는다. 증상을 묻기 전에는 말하지 않는 규칙, 용어 일괄 금지, END 명령의 교육 평가 전환은 채택하지 않았다. 본문에서 보고한 조현병의 정형화된 표현 문제도 전이의 한계로 기록했다.

**조현병 사례와 공통 역할 지시를 함께 공개한 JMIR 자료** — [원문 Textbox 1·2](https://mededu.jmir.org/2026/1/e78161/). Textbox 1은 조현병 사례이고 Textbox 2는 실제 공통 역할 프롬프트다. 사례의 정서·행동 맥락을 유지하며 학습자 질문에 반응하는 방법을 참고했다. 영어 전용과 발화 앞의 비언어 지문은 한국어 텍스트 목적에 맞춰 제외했다. 이 논문은 reflective Viewpoint이며 정신측정 검증과 결과 비교를 완료한 연구가 아니다. 해당 사례의 불신·적은 발화를 조현병 공통 규칙으로 쓰지 않는다. 웹 도구에서 표·본문을 확인해 추출문을 보존했으나 직접 HTML/PDF 다운로드는 HTTP 202와 빈 본문을 반환했다. 원본 바이트 파일이 있다고 주장하지 않는다.

**NIMH 조현병 설명** — [공식 자료](https://www.nimh.nih.gov/health/publications/schizophrenia). 증상의 개인차와 환각·망상·사고장애의 구분을 임상 개념의 출발점으로 삼았다. 이는 생성 프롬프트의 효과를 검증한 출처가 아니다. 구체적인 한국어 표현과 상황 조건은 여전히 연구팀의 적용 가설이다.

원문별 위치·짧은 확인 구절·적용 판단·한계는 `evidence-ledger.json`의 E1~E8에 있다. 원본 또는 추출문 해시는 `source-lock-v02.json`이 최신이다. 최초 다운로드 기록 `source-lock.json`의 JMIR ok는 본문 확인 전의 전송 상태였으며 최신 파일에서 `empty_body_unusable`로 정정했다. PatientHub를 PSYCHE/Roleplay-doh 원저자 구현으로 사용하지 않았다.

## v0.2와 달라진 생성 방식

1. **설정 준수 → 환자 관점으로의 변환을 명시.** v0.2는 사실을 지키고 해설하지 말라는 제약이 중심이었다. v0.3 R1은 임상적으로 정리된 내용을 환자의 지식·경험·자기 이해로 표현하도록 한다. 학습한 의학용어 사용은 유지한다. 근거 E1·E3·E6.
2. **증상과 말의 조직성을 별도 조건으로 사용.** v0.2의 혼동 방지 원칙을 R2에서 명시적으로 분리했다. R3은 정돈된 반응과 설정된 조직성 저하를 구분해, 모든 답을 완결된 요약으로 만들지 않게 한다. 근거 E1·E4·E7과 연구팀의 적용 가설.
3. **문맥에 적용되는 규칙을 먼저 고르게 함.** R3·R4는 모든 규칙을 매 턴 동시에 구현하지 않도록 한다. 짧음·자발성·정보 공개를 구분하고, 설정된 관심사의 자발적 표현도 허용한다. 자동 신뢰 상승이나 강제 저항은 도입하지 않았다. 근거 E3·E4·E5, 기존 M1 지적.
4. **선택적인 사례별 표현 예시 입력.** v0.2에는 없던 `speech_examples`를 v0.3에서만 지원한다. 사고과정에 지시와 예시를 제공하는 방법(E2)을 제한적으로 참고했다. 예시는 가상 작성임을 표시하고 같은 사례의 환자가 아는 fact ID를 참조해야 한다. 이 검사는 예문이 의미적으로 타당함을 보증하지 않는다. 조현병 환자 원문이나 검증된 예시 자료라고 부르지 않는다.
5. **유지한 공학적 제약도 출처를 구분.** 필수 사실 사전 점검, 전체 이력, 원문 보존, 버전·해시는 유지한다. 이 부분(E8)을 임상 논문이 검증한 발화 규칙으로 포장하지 않는다.
6. **원형의 채널·목적 차이를 기록.** R8은 비언어 지문·영어 전용·종료 후 의사 평가 전환을 제외한다. 텍스트의 말줄임표를 음성의 망설임·속도·정동 측정값으로 보지 않는다.

수정 원문은 `../../speech_module/patient_v03.txt`, 규칙별 출처·적용 유형은 `../../speech_module/patient_v03.sources.json`, 정확한 텍스트 차이는 `diff-v02-v03.patch`다. 규칙의 문헌 일치와 실제 발화의 임상 현실성은 별개다.

## 사용과 검증 범위

기본 버전은 `schizophrenia-speech-m2-v0.3`이다. v0.1/v0.2 파일과 기존 출력·평점은 보존하며 원래 템플릿으로 검증한다. CLI `--module-version schizophrenia-speech-m1-v0.2`로 이전 버전을 선택할 수 있다. 기존의 네 입력 필드는 그대로 사용할 수 있다.

v0.3의 실제 생성과 수동 응답 가져오기는 **질문별 작성자 확인이 필수**다. Python에서는 `question_reviewed=True`, CLI 준비 시에는 `--question-reviewed`로 표시한다. 작성자는 질문이 요구하는 정보가 사실에 있고 환자가 아는지 확인하고 `required_fact_ids`/`--require-fact`를 지정한다. 부족하면 먼저 새 합성 설정 버전으로 보완하거나 해당 질문의 생성을 보류한다. 표지는 자동 임상·의미 검증이 아니며 작성자가 잘못 확인할 가능성은 남는다. 미확인 상태에서도 오프라인 패킷 준비는 가능하지만 live 생성·출력 가져오기는 차단한다.

`speech_examples`는 **기본 비활성인 실험 옵션**이다. Python `allow_experimental_examples=True` 또는 CLI `--experimental-examples`로 켠다. 각 항목은 `context`, `utterance`, `fact_ids`, `provenance`, `target_feature`, `author_checked`를 갖는다. `provenance`는 `synthetic_author_example_not_patient_data`, `author_checked`는 true여야 한다. `target_feature`는 organization/spontaneity/guardedness/expression 중 의도한 특성이다. 예시는 최대 3개이고 참조 ID가 그 사례의 환자가 아는 사실에 속하는지 검사한다. 작성자는 새 사건·인과·확신 수준을 추가하지 않았는지, 실제로 해당 말하기 특성을 보여 주는지 확인해야 한다. 내용의 임상 타당성·모순·사실 참조의 의미적 적합성은 자동 검사하지 못한다. 전문의 인증 표지가 아니며 예시를 실제 환자 자료로 표시하지 않는다. v0.2는 이 추가 정보를 조용히 받아들이지 않는다.

입력 필드의 의미: `facts`는 background/treatment/subjective_experience/subjective_belief를 구분한다. `patient_knows`는 그 내용을 환자가 알고 있는지, `self_understanding`은 그 경험을 어떻게 이해하는지의 사례 서술이다. `disclosure=on_topic`은 관련 맥락의 통상 정보이고 `sensitive`는 설정된 경계와 맥락을 고려할 정보다. ‘묻기 전에는 절대 말하지 않음’이라는 고정 규칙이 아니다. communication의 organization은 말의 연결, spontaneity는 자발적인 말의 개시·확장, guardedness는 공개에 대한 걱정·태도, expression은 표현량·말투다. 네 필드는 필수 서술이므로 누락·빈 문자열이면 검증 실패한다. 기본 증상값은 자동 삽입하지 않는다. 별도 특성이 없으면 ‘추가 특성 설정 없음’처럼 명시하고, 진단명에서 증상을 보충하지 않는다. 반응 변화의 허용 조건은 이 서술 안에서 사례별로 정하며 미지정 신뢰·병식 변화는 강제하지 않는다.

음성·비언어 범위: 피치·목소리 크기·발화 속도·실제 반응 지연·표정·눈맞춤은 한국어 텍스트 출력에서 구현·검증하지 않는다. 말줄임표나 문장 수를 그 대리 임상 점수로 쓰지 않는다. 감정·걱정의 텍스트 내용과 관찰되는 정동은 구분한다.

예시 없이 확인된 질문의 패킷을 준비하는 예:

```bash
python3 -m speech_module prepare --input development/speech-m0-v01/inputs/DEV-M0-01.json --out /tmp/new-v03-run --question-reviewed --require-fact breakfast
```

위 명령도 모델을 호출하지 않는다. `generate`의 명시적 전송 함수와 구독 수동 가져오기 경로를 유지하며 추가 API는 연결하지 않았다.

동일 정보 비교에는 예시 없는 같은 입력으로 v0.2/v0.3을 준비할 수 있다. 예시의 효과를 시험하려면 같은 v0.3에서 예시 유무를 별도 조건으로 고정해야 한다. 프롬프트 변경과 추가 정보 효과를 합치지 않는다. 이번에는 새 발화 생성·우열 비교·현실성 재평정을 실행하지 않았다.

오프라인 검증은 `python3 -m unittest discover -s tests -p 'test_speech*.py' -v`로 수행한다. 예시의 출처·사례 ID 경계, 동일 정보의 버전 비교, v0.1/v0.2 기록 호환, 근거 대응 파일의 해시 보존을 검사한다. 구조 테스트 통과는 환자 역할 수행 성능이나 임상 검증이 아니다. 개발 설계 검토는 같은 작은 묶음을 GPT-6.1 Sol High·Claude Opus 5.5에 각각 1회 요청하고 원문 및 반영 결정을 `reviews/`, `review-disposition.md`에 남긴다. 실제 v0.3 발화가 없으므로 이번 설계 검토에는 수치 평점을 만들지 않는다.
