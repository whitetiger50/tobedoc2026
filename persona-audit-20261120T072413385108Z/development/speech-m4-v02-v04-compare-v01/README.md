# M4: v0.4 개발과 v0.2 동일 입력 비교

2026-11-18. **v0.4를 구현했지만 이번 단회 개발 비교에서 평균 점수 개선은 확인되지 않았다.** 같은 3사례에서 새로 생성한 6대화·24발화를 GPT-6.1 Sol High와 Claude Opus 5.5가 각각 한 번 평정했다. v0.2 평균은 **3.83/4**, v0.4는 **3.67/4**, 차이는 **−0.17점**이다. 동점 2사례, 하락 1사례다. 원평점과 계산값은 `scores.json`에 보존했다.

## 무엇을 바꿨는가

`speech_module/patient_v04.txt`는 v0.3의 R4 정보 공개·R7 대화 연속성만 바꾼 버전이다. 다른 여섯 구간과 역할 소개는 동일하다. 차이 원문은 `diff-v03-v04.patch`, 출처와 개발 판단은 `patient_v04.sources.json`에 있다.

- 이미 공개한 사실, 아직 말하지 않은 관련 사실, 면담자가 아직 답하지 않은 걱정을 구분한다.
- 재확인과 추가 설명 요청을 구분한다. 같은 짧은 사실 답은 허용하고, 추가 설명을 위해 설정 밖 사건·감정·인과를 만들지 않는다.
- 민감 정보는 질문의 구체성·설정된 경계심·실제 상호작용에 따라 범위를 정한다. 확인을 먼저 하거나, 일부를 공개하며 우려를 남기거나, 공개를 제한할 수 있다. 어느 순서도 일괄 강제하지 않는다.
- 특정 연결 문구, 표현 변주 할당량, 고정 공개 지연·확대를 넣지 않았다. 이미 공개했다고 전부 공개하거나, 다시 처음부터 숨기게 하지 않는다.

원래 문헌 근거의 범위를 넓혀 주장하지 않는다. 이번 두 구간의 세부 변경은 M3 모델 비평과 사용자 제약에 대한 공학적 개발 가설이다. 임상적으로 검증된 공개 순서가 아니다. 기본 버전은 v0.4이며 v0.1~v0.3 파일·원문·평점은 보존했다. v0.3의 근거 대응 파일과 질문 확인 정책도 그 버전대로 유지되어 과거 패킷이 계속 검증된다.

## 평균과 두 검토자의 판단

- **사례 1:** v0.2 GPT 4·Claude 4 → **4.0**; v0.4도 4·4 → **4.0**. 차이 **0**.
- **사례 2:** v0.2 GPT 4·Claude 4 → **4.0**; v0.4 GPT 4·Claude 3 → **3.5**. 차이 **−0.5**.
- **사례 3:** v0.2 GPT 4·Claude 3 → **3.5**; v0.4도 4·3 → **3.5**. 차이 **0**.

GPT의 조건 평균은 **4.00→4.00**, Claude는 **3.67→3.33**이다. GPT는 6대화 모두 최고점으로 이번 표본에서 버전을 구분하지 못했다. 이 현상은 기록하되 평가자의 일반적 성능이나 편향을 이 표본만으로 결론내리지 않는다. 두 모델의 입력·역할 해시는 같고 서로의 답이나 과거 점수는 제공하지 않았다. 모델별 검토 호출 1회, 대화별 평점 1개씩이다. 원응답·이유·근거 인용·불확실성은 `reviews/`에 보존했다.

## 목표한 문제가 실제 원문에서 어떻게 나타났는가

**사례 1: 두 버전이 실질적으로 비슷했다.** 식사·목소리에 대한 자기 이해·약물 지식·동거 사실을 간결하게 답했다. 특정 문구나 공개 지연을 모든 답변에 끼워 넣는 양상은 이 출력에서 보이지 않았다. 평점은 동점이다.

**사례 2: 추가 설명의 연속성은 일부 달라졌지만 초기 공개 문제는 남았다.** v0.4 P01에서 소리 경험을 이미 말한 뒤, P03에서는 “이웃이 저를 보고 있는 것 같아요.”라는 아직 말하지 않았던 설정된 믿음으로 이어졌다. 직전 경험 설명 전체를 다시 말하는 양상은 줄어든 것으로 Codex가 관찰했다. 이어 답을 듣지 못한 전달 우려를 다시 물었다. Claude도 그 재질문을 현실적이라고 보았다. 이 연결 표현은 모델이 해당 문맥에서 선택했으며 프롬프트가 특정 문구를 지정한 것이 아니다.

그러나 v0.4 P01은 민감 경험과 각성 원인의 불확실성을 한꺼번에 설명했다. Claude는 경계심·적은 자발성에 비해 이 공개가 빠르고 정돈됐다고 보고 3점을 줬다. v0.2는 첫 답에서 전달 우려를 묻고 후속 질문에서 소리 경험을 말해 4점이었다. GPT는 두 흐름 모두 자연스럽다고 보고 4점씩 줬고, Claude도 즉시 일부 공개가 설정상 허용된다는 불확실성을 남겼다. 그러므로 특정 공개 순서를 임상 정답으로 확정하지 않는다.

**사례 3: 반복에 대한 평정상 개선은 확인되지 않았다.** 두 버전 모두 일과 답변에서 오늘 걸은 일까지 먼저 말한 뒤, 다음 오늘 활동 질문에 비슷한 내용을 다시 답했다. Claude는 두 버전 모두 연속성이 다소 기계적이라고 보고 3점을 줬다. 한편 질문 자체가 같은 사실의 재확인을 요구하므로 같은 짧은 답을 하는 것만으로 실패라고 단정하지 않는다.

**추가 사실 충실도 우려가 있다.** v0.4 P03은 “오늘도 오후에 일어나서 집 근처를 좀 걷고 왔어요.”라고 했다. 오늘 오후에 걸었다는 사실은 설정돼 있지만 **오늘 오후에 일어났다는 사실은 설정돼 있지 않다.** 평소 오후에 일어나는 일과를 당일 사실로 구체화한 것이다. GPT도 불확실성에 이 점을 기록했으나 4점 평정은 유지했다. 이는 당일 기상 시간이 실제로 틀렸다고 입증한 것이 아니라 근거 없는 구체화에 대한 입력 충실도 우려다. 높은 현실성 평점과 구분해 보존한다.

## 지적의 수용·보류

1. **연속성 문제는 유지할 개발 과제로 수용.** 사례 2에서 경험 반복 대신 미공개 믿음으로 이어진 원문은 부분적인 변화지만, 사례 3의 재질문 대응까지 안정적으로 개선한 근거는 없다. 다음에는 재확인·추가 설명을 나눈 개발 과제로 검사할 수 있다.
2. **특정 연결 문구를 일괄 삽입하라는 제안은 채택하지 않음.** 사용자 제약과 자연스러운 짧은 답을 유지한다. 모든 재질문에 이전 말을 언급하게 만들면 새 기계적 패턴이 될 수 있다.
3. **경계심이 있으면 첫 답의 민감 공개를 항상 늦추라는 제안은 일괄 채택하지 않음.** 두 검토자의 해석이 다르고 현 사례도 즉시 일부 공개를 금지하지 않았다. 사례별 허용 범위를 더 분명히 정하는 후속 설계와 임상 검토가 필요하다. 이번 비교의 설정은 바꾸지 않는다.
4. **미설정 당일 세부의 구체화는 후속 확인 과제로 수용.** 반복을 피하려고 평소 일과를 당일 사실로 보충해서는 안 된다. 이번 입력과 출력·평점은 그대로 보존한다.

이번 점수를 본 뒤 v0.4를 다시 수정하거나 추가 평정을 받지 않았다. v0.4를 성능 개선판으로 부를 근거는 얻지 못했다. 부분적인 원문 변화와 평균 현실성 평점 향상을 구분한다.

## 비교 조건과 해석 범위

M3의 공통 `input`, `questions`, `required_fact_ids`, 시작 이력을 그대로 복사했다. 환자 설정이나 질문에 새 사실을 넣지 않았다. 양쪽 모두 공식 Codex CLI의 기존 ChatGPT 구독으로 `gpt-6.1-sol`, reasoning `high`를 지정했다. 예시는 사용하지 않았다. 노출되지 않는 temperature·불변 서버 snapshot을 고정했다고 추정하지 않았다.

후속 이력은 각 버전 자신의 실제 새 답변을 누적했다. 조건당 새 3대화·12발화이며, 과거 v0.2 출력도 재사용하지 않았다. 버전·프롬프트·생성 출처·과거 점수·상대 판정은 판독 모델에게 숨겼다. 공유 프로필이나 문체에서 짝 관계를 추측할 수 있어 완전 맹검은 아니다. GPT는 생성 모델과 같고, 두 모델의 평균은 임상 정답이 아니다.

이전 v0.3이나 과거 v0.2 점수를 이번 새 점수와 합치거나, 과거 평균과의 단순 차이를 개선으로 해석하지 않는다. 이번 비교도 조건당 생성 1회·개발 사례 3개·단회 평정이다. v0.2와 v0.4의 전체 차이이며 R4/R7만의 독립 효과를 분리하지 못한다. 임상 타당성·일반적 우월성·반복 안정성은 미확인이고 720회 최종 판독은 하지 않았다.

## 파일

- `methods.md`, `plan.json`: 출력 전 명세와 동일 입력·모델·코드 해시.
- `diff-v03-v04.patch`, `../../speech_module/patient_v04.txt`, `../../speech_module/patient_v04.sources.json`: 새 지시와 출처 범위.
- `runs/`: 6대화·24발화와 턴별 입력·공식 CLI 원출력·설정.
- `review-packet.json`, `review-role.txt`, `review-freeze.json`, `review-key-private.json`: 동일 검토 자료와 버전 대응표. 대응표는 판독 모델에게 전달하지 않았다.
- `reviews/`, `scores.json`: 각 1회 원응답·원평점·근거와 Python 집계.
- `implementation-snapshot/`: 실제 사용한 고정 구현 파일의 보존본.
- `verification.json`: 입력 일치·전체 이력·원문·호출 수·해시·인용·테스트 확인.
- `patient-speech-v02-v04.canvas.tsx`: 점수와 두 버전 원문·지적을 함께 보는 비교 화면 보존본.
