# M0 검토 반영 결정

2026-11-18. Codex 작성. 근거는 같은 폴더의 `feedback.md` 실제 응답이다. 전부 구현 전 설계 위험이며 관측된 발화 실패·전문의 평가가 아니다. 검토 1회, 추가 검토 0회다.

1. **설명형/반응형 구분: 수정 수용.** 질문 대응, 환자 시점, 역할 해설·증상 목록 삽입 여부를 원문 점검 질문으로 남긴다. 다만 ‘진단명을 먼저 말함’이나 의학용어 사용만으로 실패 판정하지 않는다. 사례에 제시된 자기 이해와 치료 경험에 맞는 표현을 허용한다. 새 점수척도나 자동 임상 판정기는 만들지 않는다.
2. **설정 정합성: 수정 수용.** 사례마다 병식/귀인, 치료 경험/용어, 경계심/공개, 조직성/주제에 대한 작성자 점검을 둔다. ‘병식이 높으면서 망상을 확신하면 오류’라는 이분법은 자동 제약으로 채택하지 않는다. 이번 자료만으로 그 조합을 일괄 금지할 근거가 없으며, 구체적 사례 문장과 수동 검토가 필요하다. 치료 기간만으로 특정 약 이름을 반드시 알아야 한다는 규칙도 채택하지 않는다.
3. **사실/대화 상태: 부분 수용·일부 보류.** 전체 이력을 매번 제공하고 이미 공개된 내용, 질문의 잘못된 전제, 민감한 정보 공개의 연속성을 지시한다. 공개 내용은 원문 이력이 근거이며 숨은 신뢰 점수나 LLM 요약 메모를 추가하지 않는다. 일상 세부의 자유 창작은 M0에서 보류한다. 사소함의 경계가 불명확하고 사실 보존 검사를 어렵게 한다. 설정 밖 사실은 확정하지 않되 매번 ‘모르겠다’라는 고정 문구를 쓰지 않도록 한다. 이는 현실성 개선의 증거가 아니라 보수적인 구현 선택이다.
4. **빈도에 따른 증상 모방: 수용.** 증상 빈도, 반복 단어, 강제 문장 수를 두지 않는다. 맥락에 따른 변화도 사례에 명시된 경우에만 따른다. 모든 망상 관련 질문에서 조직성이 저하된다는 일반 규칙으로 확대하지 않는다.
5. **비교/평가 공정성: 일부 수용·결정 보류.** 향후 B/T에 동일 환자 사실·의사소통 정보·전체 이력·질문을 제공하는 공통 payload를 사용한다. B의 원형 및 허용된 입력 자리를 소스와 대조하기 전에는 B 어댑터나 약한 대체 프롬프트를 만들지 않는다. 원형의 입력 구조가 이를 수용하지 못하면 정보량 일치 보조 조건 또는 비교 범위를 실행 전 결정하고 변경을 기록한다. 확인 사례·질문·B/T 프롬프트·모델·설정 해시는 확인 출력 전에 동결한다. 아직 동결/실행하지 않았다. M0는 점수 없이 원문·구조만 점검한다. 개발 중 판독 점수를 전면 금지하라는 제안은 기존 파일럿 계획의 변경이므로 지금 채택하지 않는다. 개발 자료와 새 확인 자료 분리 원칙은 유지한다. 반복 판독은 임상 타당성의 대체가 아니다.

구현 순서: 세 개발 사례 → 입력 검증과 전체 이력 기반 프롬프트 → 전송 함수 주입 및 수동 응답 가져오기 → 해시/원문/실패 기록 → 구조 테스트. Claude는 이번에 구현이나 발화 원문을 보지 않았다. M0 구현 후 비평이 완료됐다는 주장을 하지 않는다.

실제 환자 자료·전문의 평정·48대화 생성·720회 판독·성능 비교는 미실시다. 기존 파일럿 계획과 과거 연구 파일은 변경하지 않는다.
