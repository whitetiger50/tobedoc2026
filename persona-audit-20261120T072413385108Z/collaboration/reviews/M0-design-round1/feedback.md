# M0 설계 검토 (구현 전, 관측 결과 없음)

아래는 모두 **설계 위험**입니다. 실제 생성 실패로 관측된 것은 없습니다.

## 중대한 문제

### 1. 설명형 답변과 환자 반응의 판별 기준이 없음 (심각도: 높음)
- **위치:** 목표 "'환청·망상이 있다'고 설명하는 기능을 넘어", 모듈 1 "역할을 해설하지 않는다"
- **영향:** 핵심 목표에 조작적 정의가 없습니다. 그래서 개발 중 개선 여부를 판단할 수 없습니다. 판독자가 증상 노출량을 현실성으로 착각할 위험도 있습니다.
- **수정:** 설명형 신호를 원문 판독용 체크 항목으로 명시합니다.
  - 자기 증상을 3인칭이나 교과서식으로 요약함
  - 질문에 답하지 않고 증상 목록을 제시함
  - 묻지 않은 진단명을 꺼냄

  반응형은 "질문 내용에 직접 응답하고, 경험은 환자가 믿는 사실로 서술함"으로 정의합니다.
- **다음 검사:** 증상과 무관한 질문(식사, 수면, 가족)에서 증상 서술이 끼어드는지 원문으로 확인합니다.

### 2. 설정 간 정합성 규칙 부재 (심각도: 높음)
- **위치:** 입력의 "환자 설정"과 "의사소통 설정"이 분리되어 있지만, 둘 사이의 제약은 없습니다.
- **영향:** 서로 모순되는 조합이 가능해집니다.
  - 병식이 높은데 망상을 확신함
  - 치료 경험이 길어 "환청", 약 이름 같은 용어를 써야 자연스러운데 용어를 회피함

  거꾸로 "의학용어 부족"이 고정관념으로 기본값이 될 수도 있습니다.
- **수정:** 사례 작성 단계에 짧은 정합성 점검표를 둡니다. 예: 병식 ↔ 증상 귀인 방식, 치료 이력 ↔ 용어 사용 가능성, 경계심 ↔ 공개 범위. 의학용어 사용은 치료 이력에서 도출하고, 진단명에서 도출하지 않습니다.
- **다음 검사:** 병식이 높고 치료 경험이 있는 사례 하나를 두고, 자연스러운 용어 사용이 억제되지 않는지 봅니다.

### 3. 사실 보존과 대화 상태가 충돌함 (심각도: 높음 — 가장 큰 실패 위험 가설)
- **위치:** "없는 과거 사건…을 임의로 확정하지 않는다", "무엇을 이미 말했는지"
- **영향:** 면담은 설정에 없는 세부를 계속 묻습니다. 이때 두 방향의 실패가 예상됩니다.
  - 과도한 "모르겠다": 회피나 비협조로 읽혀 고정관념을 강화합니다.
  - 즉석 창작: 이후 턴에서 같은 세부가 바뀝니다.
- **수정:** 설정에 없는 세부의 허용 범위를 둡니다. 사소한 일상 세부는 허용하고, 사건·수치·약물은 금지합니다. 한 번 말한 세부는 공개 기록에 남겨 다음 턴 입력에 포함합니다.
- **다음 검사:** 다회차 대화에서 같은 사실을 시차를 두고 다시 묻고, 원문으로 일관성을 확인합니다.

### 4. 증상 표현 조건이 빈도로 구현될 위험 (심각도: 중간)
- **위치:** "조직적인 답과 증상이 드러나는 답의 범위를 설정한다"
- **영향:** 구현 시 "N회 중 1회 탈선"처럼 확률이나 문장 수로 조절되기 쉽습니다. 이는 기계적 모방입니다.
- **수정:** 범위를 빈도가 아니라 **주제와 맥락**으로 정의합니다. 예: 망상 관련 주제나 스트레스 상황에서 조직성이 저하되고, 일상 주제에서는 유지됩니다. 어휘 목록이나 문장 수 제한은 넣지 않습니다.
- **다음 검사:** 같은 사례에 일상 질문과 망상 관련 질문을 섞습니다. 변화가 주제를 따라가는지, 무작위인지 원문으로 봅니다.

### 5. 비교·평가의 공정성 (심각도: 높음)
- **위치:** "B와 T의 … 사례·질문·실행 설정을 같게", LLM 판독자 3종 × 5회
- **영향:**
  - **입력 불균형:** T만 의사소통 설정과 공개 기록을 받으면, 차이가 모듈 효과인지 정보량 효과인지 분리되지 않습니다.
  - **확인 자료 미고정:** 확인 사례와 질문을 언제 고정하는지 명시가 없습니다.
  - **판독자 최적화:** 판독자 점수를 보며 T를 반복 수정하면 판독자에 과적합됩니다.
  - **반복 판독의 한계:** 5회 반복은 판독 안정성을 보일 뿐, 타당성의 근거가 아닙니다.
- **수정:**
  - B에도 동일한 환자 사실을 제공합니다.
  - 정보량을 맞춘 B 조건을 둘지 결정합니다(질문).
  - 확인 사례, 질문, 프롬프트 해시를 T 출력을 보기 전에 고정합니다.
  - 개발 중에는 판독자 점수를 쓰지 않고 원문 검토만 합니다.
- **다음 검사:** 사전 고정 파일의 해시와 커밋 시점이 확인 실행보다 앞서는지 기록합니다.

## 유지할 장점
1. 진단명만으로 모든 특성을 강제하지 않고, 짧은 대답을 거절로 취급하지 않는 원칙
2. 개발 사례와 확인 사례의 분리, 그리고 판독 절차를 검증된 척도로 주장하지 않는 범위 설정

## 다음 작업 우선순위
1. **사례 스키마 구현:** 정합성 점검표와 공개 기록을 포함합니다. 개발 사례 3개는 대비되게 구성합니다.
   - 병식이 높고 조직적인 사례
   - 경계심이 높고 공개가 적은 사례
   - 망상 주제에서 탈선하는 사례
2. **원문 검토용 질문 묶음 작성:** 일상 질문, 직접 증상 질문, 같은 사실의 재질문, 신뢰 변화 시점을 포함합니다. 1, 3, 4번 실패를 사람이 읽어 판별합니다.
3. **B 입력 동등성 결정과 확인 세트 사전 고정:** 판독자 파일럿보다 먼저 합니다.
