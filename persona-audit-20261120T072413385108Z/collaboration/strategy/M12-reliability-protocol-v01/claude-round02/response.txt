# M12 실행 전 최종 지적

수정안은 대부분 타당합니다. 그대로 실행하면 결과 해석이 오염될 수 있는 항목만 아래에 적습니다. 새 점수, 새 발화, 추가 연구 제안은 없습니다.

## 먼저 정정: 제 1차 비평의 오류

**[근거]** Codex의 반론이 맞습니다. 두 열이 서로 다른 상수일 때를 보면 다음과 같습니다.

- 행 평균이 모두 같아서 MSR=0입니다.
- 잔차도 0이라서 MSE=0입니다.
- 열 차이만 있으므로 MSC>0입니다.

따라서 ICC(A,1)=0/(k·MSC/n)=0이고, 일관성 ICC만 0/0입니다. 모든 형태에서 미정의라고 한 제 서술은 틀렸습니다. 두 열이 같은 상수일 때만 둘 다 0/0입니다. "계수가 정보를 주지 않는다"는 일반화를 좁힌 것도 수용합니다.

## 반드시 고칠 것

### 1. 역할문 예시 `fact:living`이 조작 표적을 가리킵니다
- **[근거]** 대조 3쌍의 조작은 모두 동거 사실 반전입니다. 역할문의 유일한 fact ID 예시가 `fact:living`입니다.
- **[의견]** 이 문구는 15개 전체에 같은 주의 편향을 줍니다. 조작본에서는 탐지를 부풀리고, 자연본에서는 거주 관련 과잉 지적을 유도할 수 있습니다. 그러면 1차 조작 확인 지표인 "표적 턴 지목"과 "grounding 0"이 이 문구에 오염됩니다.
- **수정**: 예시를 `fact:<ID>` 같은 중립 표기로 바꿉니다.
- **[확인 필요]** 실제 입력 프로필이 fact ID를 붙인 형태로 제시되는지 확인하세요. ID가 없으면 rating 0/1의 context_refs가 형식상 충족될 수 없습니다.

### 2. grounding의 "보충 불허" 규칙이 사전 비교쌍과 충돌할 수 있습니다
- **[근거]** 역할문은 "이 과제는 프로필 밖의 새 사건·구체 시각·인물 속성·원인을 사실로 보충하는 것을 허용하지 않는다"고 단정합니다. 그런데 사전 비교쌍(M6 v04−v02, M9 examples−none)은 생성 프롬프트가 서로 다른 조건끼리의 비교입니다.
- **[확인 필요]** 각 조건의 생성 지시가 실제로 같은 보충 허용 범위를 가졌는지 원 프롬프트로 대조하세요.
- **수정**: 허용 범위가 다르다면 둘 중 하나를 택합니다.
  - 한 조건이 지시받지 않은 기준으로 평가된다는 혼입을 비교쌍 해석에 사전 기록한다.
  - 역할문 문장을 조건 중립적으로 바꾼다.

  어느 쪽이든 실행 전에 정해야 합니다.

### 3. 주 ICC로 바꾼 일원 모형에 검증 fixture가 없습니다
- **[근거]** M5 회귀 검사(α=5/56, ICC(A,1)=1/6)는 이원 모형과 α만 검증합니다. 새 주 지표인 ICC(1,1)/(1,3) 코드는 검증되지 않은 상태입니다.
- **수정**: 실행 전에 Python으로 일원 공식을 검사합니다.
  - 일원 ANOVA 평균제곱을 직접 계산하는 독립 구현과 결과를 대조합니다.
  - 상수 행렬에서 0/0을 반환하는지 확인합니다.
  - 열마다 다른 상수인 행렬을 이원/일원 각각에서 처리하는 fixture를 둡니다.
- **[확인 필요]** "KooLi 정정의 (k−1) 분모"는 정정문에 기대지 말고 Shrout & Fleiss(1979)의 정의와 직접 대조하세요.

### 4. 일원 모형의 정당화 문구가 실행 절차와 모순됩니다
- **[근거]** 실행 절차는 "각 15개 블록 후 다음 반복"이므로 라운드가 시간 블록이 됩니다. 이 경우 라운드 라벨이 교환 가능하다는 것은 확인된 사실이 아니라 가정입니다.
- **수정**: 문구를 "일원 모형을 사전 지정하고, 교환 가능성은 가정이며, 이원 ICC(A,1) 민감도로 라운드 효과를 점검한다"로 바꿉니다.
- ICC(1,3)은 세 회차 평균의 신뢰도입니다. 단회 운영의 근거로 쓰지 않는다는 문장을 분석 결정에 명시하세요(Astra 지적과 같음).

### 5. 파서 해시를 동결하기 전에 미정 규칙 두 가지를 정하세요
- **인용 문자 일치의 정규화 범위**: 예를 들어 NFC 정규화, 공백, 문장부호, 앞뒤 따옴표를 어떻게 처리할지 정해야 합니다. 정하지 않으면 사후 판단으로 "인용 불일치" 건수가 달라집니다.
- **`rating=null`이면서 `uncertain=true`인 출력의 처리**: 허용할지, 형식 실패로 볼지 정합니다.

## 실행 차단 사유가 아닌 것
나머지 변경은 남은 쟁점을 해소했다고 봅니다. 해당 항목은 다음과 같습니다.

- 혼입 명시 후 진행
- 블라인드 격리
- 버전 기록
- 자기계열 한계 기록
- 3×3 비독립 처리
- 주 CI 미보고
- 결측 분리
- G-Eval/PatientSim 범위 정정

위 1~5를 반영하면 15개/90회 1회 실행을 막을 오류는 제가 보기에 남지 않습니다. 다만 저는 Claude 평정 모델과 같은 계열이므로 이 판단의 독립성에는 제한이 있습니다.
