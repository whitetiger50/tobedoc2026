# M10 후속 전략 검토 (2026-11-19 KST)

**범위**
- 이번 입력(1차 Claude 응답, Astra 1·2차 검토, Codex 반론, 측정 감사 JSON, M1/M2 연대기 보충, 지적 위치 감사 요약)만 검토했습니다.
- 도구 호출, 저장소 열람, 생성, 평정은 하지 않았습니다.
- 수치는 제공된 감사 JSON과 대조했습니다. M3·M4·M6·M7·M9의 조건 평균과 M1 평균을 손으로 다시 계산해 보았고 모두 일치합니다.

**표기**
- **[관찰]**: 입력 원문이나 수치에서 바로 확인되는 내용
- **[추론]**: 제 해석
- **[정정]**: 제 1차 주장을 철회하거나 축소하는 내용
- **[제안·미승인]**: 실행되지 않은 제안

## 1. 요약

1. Codex의 범위 정정 대부분과 새 평정 보류에 **동의합니다.** 특히 제가 1차에서 제안한 prefix 12평정과 5/6·3/6 결정 규칙은 근거 없는 임계값이었습니다. **철회합니다.**
2. 다만 세 가지가 남습니다.
   - M1 자료가 제 "척도 퇴화" 서술의 반례입니다.
   - M5 대조 문구에 묶음 구성 조건이 빠져 있습니다.
   - 최종 집계(세 판독자 중앙값의 중앙값)에 개발 패턴이 이어질 때의 함의를 보고 계획에 넣어야 합니다.
3. B 감사에는 입력 공정성 항목 몇 가지가 빠져 있습니다. 대표적으로 사실 ID 사전 점검을 양쪽에 똑같이 적용하는지, 번역 동결 시점, 앵커 출처와 B 출처가 겹치는지입니다.
4. 새 생성, 수치 평정, 최종 자료 사용 없이 계획을 정리할 수 있습니다. 추가 검토 왕복도 필요하지 않습니다.

## 3. 질문 1: 해석 범위 정정과 새 평정 보류에 동의하는가

**동의합니다.**
- Astra의 8평정 보류에 동의합니다. 바뀔 수 있는 판단이 "두 원문에 대한 단독 제시 반응의 반복"이라는 기술 주장뿐이고, 지금 그 주장이 필요한 결정은 없습니다.
- 제 prefix 진단의 철회, 위치 감사에 게이트를 붙이지 않은 것에도 동의합니다.

**남은 반례와 누락 세 가지**

1. **M5 대조 문구에 조건이 빠져 있습니다 [추론].**
   - Astra 2차 문구에는 대조쌍(Q775/Q911, Q996/Q472, Q710/Q605)이 원본과 **같은 묶음 안에** 거의 같은 형태로 있었다는 조건이 없습니다.
   - 판독자는 나란히 비교할 수 있었습니다. 따라서 "단독 제시에서도 같은 반응이 나온다"는 일반화를 막는 조건으로 이것을 문구에 넣어야 합니다.
   - 예: "…이 세 대화에서, 원본이 같은 묶음에 함께 제시된 조건에서, 일관되게 낮아졌다."
   - Codex 반론에는 이 마스킹 문제에 대한 응답이 없습니다.

2. **"척도 천장"의 범위를 좁혀야 합니다.**
   - M1이 보여주듯 v0.1의 입력 누락 결함에는 두 판독자 모두 반응했습니다.
   - 정확한 서술은 이렇습니다. "v0.2 이후 개발 대화에서 GPT는 거의 최고점에만 머물렀고, 이 구간에서 버전을 구분할 정보는 거의 없었다."
   - 이렇게 한정하지 않으면 "GPT 판독은 정보가 없다"로 과잉 일반화됩니다. 반대 방향으로도 주의해야 합니다. M1 하나로 "실제 결함을 탐지한다"고 말하지 않습니다(n=3, 단회 평정, 자기평가).

3. **위치 감사를 읽는 방식 [관찰 + 추론].**
   - 관찰:
     - M8 Claude: 18개 위치 중 17개가 유도 구간(P05–P07)
     - M9 Claude: 15개 중 10개가 유도 구간
     - GPT: M8·M9 모두 중립 구간만 지적
   - M8→M9에서 질문 세트는 같은데 Claude의 중립 위치가 1개에서 5개로 늘었습니다. 하지만 새 생성과 검토 과제(문체 과제 추가)가 함께 바뀌었으므로 원인을 귀속할 수 없습니다.
   - 추가 혼입 [추론]: grounding 검토 과제가 유도 질문을 겨냥해 설계됐다면, 지적이 유도 구간에 모이는 것은 **과제가 주의를 어디에 배분시켰는지**를 반영할 수 있습니다. 이번 입력에는 과제 원문이 없어 확인하지 못했습니다.
   - 결론: 이 감사는 "M8·M9 총점이 유도 구간을 포함한 대화 전체의 평정"이라는 **보고상의 단서**로만 씁니다. 어떤 결정의 근거로도 쓰지 않습니다.

## 4. 질문 2: B 감사(입력 공정성)와 측정 타당성 게이트 분리에서 빠진 것

분리하는 방향에 동의합니다. 제 1차 Stop/Go 규칙의 "원문 그대로 또는 최소 포팅 가능 → B로 확정"이 최종 비교 실행 승인처럼 읽힐 수 있었다는 점도 인정합니다. **B 확정은 이름 붙이기일 뿐이고, 최종 실행에는 별도의 동결과 사용자 승인이 필요합니다.**

### 입력 공정성 감사에 추가할 항목 [제안·미승인]

1. **사전 사실 점검을 양쪽에 대칭으로 적용하는가**
   - v0.2에는 `required_fact_ids` 누락 시 생성을 중단하는 기능이 있습니다 [관찰: M1 보충].
   - 이것이 T 프롬프트의 일부인지, 양쪽 입력 품질 관리 절차인지 정해야 합니다.
   - T에만 적용되면 B/T 차이에 입력 완성도 차이가 섞입니다. M1→M2 이후 비교에서 이미 겪은 혼입이 그대로 반복됩니다.

2. **정보 대등성 대조표**
   - T가 받는 구조화 필드(facts, patient_knows, disclosure, communication, history, current_question)를 B가 어떻게 받는지 필드별로 대조합니다. 각 필드를 "그대로 전달 / 서술문으로 변환 / 누락"으로 표기합니다.
   - 면담자 문맥(`authored_context`)과 질문 스크립트가 양쪽에서 같은 해시인지도 확인합니다.

3. **번역과 변환을 동결하는 시점**
   - 번역이 필요하면 번역 주체와 번역문 해시를 B 출력을 보기 전에 고정합니다.
   - 번역은 "최소 포팅 이상"으로 분류하는 데 동의합니다.

4. **런타임 조건이 같은가**
   - 생성 모델, 추론 설정, CLI를 양쪽에 똑같이 씁니다.
   - T 실행 시 v02를 명시하고 해시를 대조합니다. 과거 기본값 v04로 조용히 실행될 위험은 Codex 반론에서 다뤄지지 않았으므로 게이트로 남깁니다.

5. **출처의 사용 조건**
   - E3·E4·E6 각각의 사용 허가나 라이선스, 고정 커밋이나 버전 해시를 기록합니다.
   - 평정 척도는 이미 PATIENTSIM 고정 커밋을 쓰고 있으니 같은 방식을 따르면 됩니다.

6. **조건부 확인 [추론]**
   - 만약 B 후보가 Realism 앵커와 같은 원 출처(PATIENTSIM 계열)에서 나왔다면, 앵커가 그 시뮬레이터 출력 수준에 맞춰 만들어졌을 가능성이 있습니다.
   - 이것은 입력 공정성이 아니라 **측정 쪽의 비대칭**이므로 측정 게이트에 기록합니다.
   - E3의 정체는 이번 입력에서 확인할 수 없습니다.

### 측정 타당성 게이트

- **새 측정이 아니라 주장 범위를 정하는 문서**로 두기를 제안합니다. 내용은 다음과 같습니다.
  - (a) 최종 결과로 허용되는 문장과 허용되지 않는 문장 목록
  - (b) 판독자별 분포 보고 방식
  - (c) 외부 임상 앵커 부재를 명시
- **중앙값의 중앙값에서 따라 나오는 산술적 함의 [추론, 조건부]**
  - 정수 중앙값 세 개 중 GPT가 4, Claude가 3에 머물면, 세 값의 중앙값은 Gemini 중앙값을 3~4 사이로 자른 값이 됩니다. 즉 **최종 점수가 사실상 세 번째 판독자에 의해 결정됩니다.**
  - 개발 패턴이 홀드아웃이나 B 출력에도 이어진다는 보장은 없습니다. M1과 M9에서 GPT도 3점을 줬습니다. Gemini의 개발 자료는 이번 입력에 없습니다.
  - 그러니 예측으로 쓰지 말고, **판독자별 중앙값과 어느 판독자가 중앙 위치였는지를 함께 보고하도록 사전에 명시**하면 충분합니다. 집계 방식이나 패널을 바꾸는 제안이 아닙니다.
- **식별 정보 없음 표기 기준**
  - 제가 1차에 쓴 "천장이나 상수"는 모호했습니다.
  - "한 판독자의 모든 원평정이 같은 값"이라는 정의적 기술로만 한정합니다. 임계값은 두지 않습니다.

## 5. 질문 3: 두 목표를 분리하는 최소 문서화 계획

기존 점수를 재분류하거나 재평정하지 않고, 아래 다섯 가지를 **보충 문서(addendum)** 하나로 남기면 충분하다고 봅니다 [제안·미승인].

1. **목표 정의 두 줄**
   - 자연 면담 현실성: 유도하지 않는 질문에 대한 환자 발화가 그럴듯한가
   - 유도 질문 근거 보존: 전제를 깔거나 구분을 요구하는 질문에서 합성 프로필이 지지하지 않는 사실을 만들어내거나 받아들이지 않는가
   - 후자의 참조 기준은 합성 프로필입니다. 따라서 이것은 **임상 현실성이 아니라 설정 충실도**라고 명시합니다.

2. **기존 수치가 어디에 해당하는지 표시**
   - M8·M9의 Realism 총점은 두 목표가 섞인 대화 전체에 대한 평정이라고 한 문장으로 적습니다.
   - 위치 감사는 이 단서를 뒷받침하는 서술 자료로만 인용합니다.

3. **면담자 책임 규칙**
   - 스크립트 질문이 아직 공개되지 않은 내용을 전제할 때가 있습니다(Astra의 사례 2 P07 소리 사례).
   - 이 경우 환자가 전제를 받아들인 것을 자동으로 환자의 사실 오류로 세지 않습니다. 특정 반응(예: 놀람, "그건 어떻게 아세요?")을 유일한 정답으로 정하지도 않습니다.
   - 제가 1차 판독자로서 제시한 필수 반응을 채택하지 않은 것은 옳았습니다.

4. **기록 단위 규칙**
   - 사실 범위와 모순, 공개 연속성, 요청된 설명의 격식성을 구별합니다.
   - 같은 사건이 issues와 grounding 양쪽에 있으면 한 사건으로 연결합니다(Codex 수용 4번과 같음).

5. **최종 스크립트 결정을 설계 논리로 미리 고정**
   - 최종 질문 스크립트에 유도 질문을 넣을지는 개발 점수가 아니라 주장 목적에 따라 동결 전에 정합니다.
   - 넣는다면 최종 Realism도 섞인 대화의 평정이라고 보고합니다.
   - 그 근거 보존을 따로 주장하려면 별도 도구가 필요합니다. 이것은 지금 만들지 않는 **미래 과제**로만 기록합니다.

이 다섯 가지면 지금 필요한 범위는 충분합니다. 유도 질문의 효과를 식별하는 실험은 필요성이 생겼을 때 동시 수집 설계로 따로 판단한다는 Codex 의견에 동의합니다.

## 6. 질문 4: 새 생성·평정·최종 자료 없이 정리할 수 있는가

**정리할 수 있습니다.** 남은 작업은 모두 문서 작성이나 호출 없는 감사입니다.

1. 보충 정정 문서: 이 응답 §2의 정정과 Codex·Astra의 축소 문구. 동결된 과거 기록은 수정하지 않습니다.
2. B 입력 공정성 감사(§4 항목 포함, 호출 0회)
3. 주장 범위 문서(측정 게이트)
4. 최종 동결 점검 목록: B/T 해시, v02 명시, 스크립트, 검토 역할, 판독자별 보고 사전 명시
5. 사용자 결정이 필요한 지점: 최종 스크립트에 유도 질문을 포함할지, B 감사 결과가 "재구성만 가능" 또는 "정보 대등성 불가"일 때 주장을 축소할지

**추가 멘토 왕복은 제안하지 않습니다.** B 감사 결과가 위 세 갈래(원형·최소 포팅 / 재구성만 가능 / 불성립) 중 어디에 해당하는지는 1차에 정한 기준대로 사용자가 판단할 수 있습니다.

- **Astra 1차** [관찰]
  - 14/18 일치, M6 3.778, Claude 4점 10개 / 3점 8개, 1/18 해상도 모두 감사 JSON과 일치합니다.
