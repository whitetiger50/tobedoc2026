# 다음 개발자료의 질문별 작성 점검 계획

이 문서는 다음 작업의 작성 기준을 정의한다. 현재 사례·질문·환자 입력·코드는 변경하지 않는다. 환자 발화의 정답 문장이나 새로운 평가 척도가 아니다.

특정 사실을 끌어내려는 문항에 대해 작성자가 다음 항목을 한 번 대조한다.

1. **목적:** 자연스러운 열린 질문, 특정 사실 확인, 재확인, 의도적 잘못된 전제·정보 누락 가운데 무엇을 보려는지.
2. **대상:** 누구의 어떤 경험·행동·계획을 묻는지. 질문이 특정 사실을 반드시 공개하도록 강요할 필요가 있는지도 구별한다.
3. **시간·확실성·관계 범위:** 평소/오늘/특정 시점, 진료 전/진료 때, 가능성/확정, 동시 발생/인과, 동거인 존재/가구 구성의 배타성을 구별한다. 기재하지 않은 부재나 독점 관계를 추론해 채우지 않는다.
4. **프로필 근거:** 관련 fact id와 원문 구절, `self_understanding`, 환자가 아는 범위, 의도된 정보 공백을 대응시킨다. 필수 fact id가 있다는 것만으로 의미 호환성이 확인된 것은 아니다.
5. **면담 이력:** 해당 정보가 이미 공개됐는지, 현재 문항이 정당한 재질문인지, 면담자가 아직 말하지 않은 정보를 먼저 전제했는지 확인한다. 짧게 같은 사실을 다시 답하는 것은 허용한다.
6. **중립성과 완료:** 질문이 정답이나 새 사실을 먼저 알려주지 않고 의도한 범위와 맞으면 점검을 마친다. 모든 질문을 좁은 정답 유도로 바꾸지 않는다. 잘못된 전제나 범위 공백이 실험 목적이면 없애지 않고 목적을 표시한다.

관측 예시는 M13 사례2 D08/P08이다. 질문은 진료 전 활동, 근거 사실은 진료 때 대화 주제여서 특정 goal을 끌어내기 위한 문항으로는 시점이 어긋난다. 앞으로 같은 목적의 새 문항을 작성할 때 범위를 맞춘다. 과거 M13의 질문·설정·출력·평점은 그대로 보존한다.

작성 점검으로 확인하는 것은 질문과 근거의 정합성이다. 환자 행동이 나아졌는지, 전체 현실성 점수가 달라졌는지는 실제 대조가 있을 때 따로 판단한다. 자동 검사기나 새 입력 스키마를 구현한 문서가 아니다.
