# M14: v0.2 개발 재개 판단과 다음 계획

2026-11-19 KST. 사용자 요청에 따라 Astra와 별도 Claude Opus 5.5 high의 최초·후속 비평을 각각 2회 받았다. 실제 응답을 읽고 Codex가 반론·정정과 기존 자료 근거를 전달한 뒤 최종 계획을 정리했다. **환자 프롬프트·모듈·평가 기준·기존 생성 입력은 수정하지 않았고 새 발화·수치 평정은 없다.**

**재개 판단:** 동일 평가자의 반복 일관성과 지정 결함의 위치 지목을 근거로, 특정 문제를 다루는 작은 개발은 재개할 수 있다. 자연 발화의 미세한 총점 순위나 임상 타당성까지 검증됐다는 뜻은 아니다. 모델 간 점수 차이 자체를 실패 조건으로 삼지 않는다.

**다음 우선순위:** v0.2를 유지하며 차기 개발자료의 질문과 프로필 사실이 같은 대상·시간·지식 범위를 다루도록 작성 점검을 명확히 한다. M13 사례2처럼 ‘진료 전 활동’ 질문과 ‘진료 때 대화’ 목표가 어긋나는 문제를 먼저 분리한다. 입력 과제 정비이며 환자 생성 프롬프트의 개선 효과라고 부르지 않는다.

**보류한 개입:** 관련 목표의 자발적 설명, 의사가 다시 물어 생긴 짧은 재답변, ‘둘이’라는 경계 표현만으로 반복·공개 억제나 일반 범위 금지문을 추가하지 않는다. 인위적인 역할 이탈 대조의 탐지도 자연 원문의 상습 결함 근거가 아니다. 현재 검토한 다섯 위치에서는 직접 환자 프롬프트 개입을 선정하지 않았다. 전체 v0.2가 무결함이거나 최적화됐다는 결론은 아니다.

**종료와 다음 결정:** 이번 기존 지적 다섯 위치 검토는 끝냈다. 다음 작성 점검을 한 번 마치고, 앞으로 정해진 개발 범위를 다 보면 명확한 생성자 결함 한 가지를 고르거나 v0.2 유지로 그 주기를 닫는다. 결함을 찾을 때까지 감사·평정을 반복하지 않는다. 후보를 만들 때는 v0.4~v0.6의 규칙·예시 추가와 다른 작동 원리를 먼저 설명한다.

- 최종 계획: `next-development-plan.md`
- 다음 질문 작성 점검 항목: `question-readiness-plan.md`
- 수용·보류·반박: `decision.md`
- 실제 Astra 비평: `astra-round01.md`, `astra-round02.md`
- 실제 Claude 비평: `claude-round01/response.txt`, `claude-round02/response.txt`
- Codex의 실제 반론: `codex-response-round01.md`, 전달 입력 `round02-request.md`
- 호출 없는 기존 자료 발췌·노트: `existing-natural-evidence.json`, `bounded-origin-audit.json`, `literal-scope-audit.json`
- 입력·보호 파일·실제 응답·기록의 해시: `scope-freeze.json`, `request-freeze.json`, `round02-freeze.json`, `verification.json`

기존 v0.5 결과는 ‘해당 설계에서 이득 미확인’으로 유지한다. 이를 총점 해상도 문제 하나로 사후 교체하자는 제안은 반박했고 Claude가 후속에서 철회했다. 단일 사례의 명백한 결함까지 제외하자는 제안도 일반 규칙으로 채택하지 않았다. 개별 진단과 여러 사례에서의 일반화 근거를 구별한다.

최종 12사례·720회 계획·주평가 기준은 그대로다. 비평은 추가 판독자나 전문의 평가가 아니며 별도 유료 API·새 모델 다운로드·패키지 설치도 없다.
