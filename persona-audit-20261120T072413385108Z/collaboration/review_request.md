# M0: 발화기 구현 전 설계 검토

상태: 설계 제안이다. 아래 모듈을 구현하거나 실제 환자 대화를 생성·검증한 결과는 아직 없다. 이번 검토는 설계의 누락과 구현 우선순위를 찾기 위한 것이다.

## 문제와 목표

실제 환자 발화 자료가 없는 상황에서, 기존 LLM에 적용하는 조현병 맞춤 발화 프롬프트를 개발한다. ‘환청·망상이 있다’고 설명하는 기능을 넘어, 주어진 가상 환자의 배경·경험·의사소통 방식과 현재 질문에 맞게 환자 입장에서 반응하도록 만든다. 최종 성능 주장은 후속 확인 자료와 평가자 검증에 따른다.

## 최소 모듈 제안

입력은 세 가지다.
- 환자 설정: 나이·생활·증상 경험·병식·치료 경험 등 고정 사실.
- 의사소통 설정: 조직성·발화 자발성·경계심·표현량 등 해당 사례에서 의도한 특성. 조현병이라는 진단명만으로 모든 특성을 동시에 강제하지 않는다.
- 면담 이력과 현재 질문: 무엇을 이미 말했는지와 질문의 맥락.

생성 프롬프트의 구성은 다음과 같이 분리한다.
1. 환자 역할과 사실 보존: 없는 과거 사건·수치·약물 정보를 임의로 확정하지 않는다. 환자처럼 말하며 역할을 해설하지 않는다.
2. 사례별 발화 방식: 일상적으로 조직적인 답과 증상이 드러나는 답의 범위를 설정한다. 모든 답변에 같은 증상 신호를 삽입하지 않는다.
3. 대화 대응: 질문과 신뢰 수준에 따라 정보 공개와 경계심을 조절하되, 짧은 대답을 자동으로 거절이라고 취급하지 않는다.
4. 출력: 외부에는 환자의 발화 텍스트만 출력한다. 내부의 증상 라벨·채점 기준·추론 설명을 환자 답변에 노출하지 않는다.
5. 연구 기록: 실제 모델 버전, 프롬프트 버전, 사례·질문·입출력, 설정과 파일 해시를 저장한다. 수치 집계는 Python으로 한다.

## 개발과 비교의 범위

- 첫 단계는 별도의 개발 사례 3~4개로 입출력·사실 보존·환자 시점 유지부터 확인한다. 지금 이 요청에는 개발 사례의 실제 발화가 없다.
- 기존 정신과 페르소나 B와 개발 모듈 T의 생성 모델·사례·질문·실행 설정을 같게 둔다. 원형 페르소나를 임의의 약한 프롬프트로 대체하지 않는다.
- 개발 중 비평에 사용한 사례는 최종 프롬프트 성능 확인의 미사용 사례로 취급하지 않는다.
- 평가자 검증 파일럿은 PATIENTSIM Realism의 정신과 적용을 고정된 GPT-6.1 Sol / Claude Opus 5.5 / Gemini 4 Argon으로 각 5회 독립 판독하는 별도 절차다. 이것은 이미 검증된 조현병 현실성 척도가 아니다.
- 초기에 환자 데이터 증강의 임상적 유효성이나 실제 환자와의 동등성을 주장하지 않는다.

## 이번에 답해 줄 질문

1. 위 분리에서 현실적인 조현병 발화 생성에 꼭 필요한 요소가 빠졌는가?
2. 가장 큰 실패 위험은 임상 내용, 프롬프트 구조, 대화 상태 가운데 어디에 있는가? 실제 증거 없는 가설임을 구분해 달라.
3. 구현을 작게 시작한다면 무엇부터 만들고, 어떤 원문 사례를 봐야 실패를 알아볼 수 있는가?
4. 과도한 조절 변수를 추가하지 않으면서 기계적 모방과 설정 모순을 줄일 방법은 무엇인가?

요청한 형식의 비평과 다음 확인 과제를 제시하라. 환자 대화의 샘플 점수나 연구 결과를 만들어내지 마라.
