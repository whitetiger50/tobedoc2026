# 2~3단어 영어 첫 답변의 판독 결과

2026-11-21 KST. 직접 작성한 일상 대화 9건을 Opus 5.5와 GPT-6.1 Sol에 각각 제시했다. 두 모델 모두 긍정·부정과 확신 부족을 직접 답으로, 되묻기를 명료화 요청으로 분류했다(각각 9/9). 두 모델의 임상 판정이 달라진 항목은 내용 빈곤이었다.

## 가상 예제와 문항별 내용 빈곤 판정

| 질문 | 첫 답변 | 두 모델의 반응 유형 | Opus 내용 빈곤 | GPT 내용 빈곤 |
|---|---|---|---|---|
| Did you set a timer for the oven? | Yes, I did. | 직접 | 음성 | 음성 |
| 같은 질문 | I'm not sure. | 직접 | 판독 불충분 | 음성 |
| 같은 질문 | Which oven exactly? | 명료화 요청 | 판독 불충분 | 음성 |
| Would you take an early ferry? | Absolutely not. | 직접 | 음성 | 음성 |
| 같은 질문 | Not sure. | 직접 | 판독 불충분 | 음성 |
| 같은 질문 | How early? | 명료화 요청 | 판독 불충분 | 음성 |
| Do you usually book a table before lunch? | No, I don't. | 직접 | 음성 | 음성 |
| 같은 질문 | Hard to say. | 직접 | 판독 불충분 | 판독 불충분 |
| 같은 질문 | Repeat that, please. | 명료화 요청 | 판독 불충분 | 음성 |

한 질문 안에서는 세 문장의 길이를 같게 했다(각각 3, 2, 3단어). 확신이 없다는 말은 화자가 취한 입장이다. 기존 기준에 따라 여섯 직접 답에 포함했다. 임상 판독자의 ‘불확실’은 가능한 소견에 두 가지 해석이 있을 때 쓰는 별도 상태다. 이번 판독에서 이 상태를 선택한 모델은 없었다.

## 판독 가능 분모

| 임상 항목 | Opus 5.5 | GPT-6.1 Sol |
|---|---|---|
| 탈선 | 판독 불충분 9/9 | 판독 불충분 9/9 |
| 내용 빈곤 | 음성 3/9, 판독 불충분 6/9 | 음성 8/9, 판독 불충분 1/9 |
| 질문 초점 이탈 | 음성 9/9 | 음성 9/9 |
| 지시 실패 | 음성 9/9 | 음성 9/9 |

두 모델 모두 내용 빈곤을 양성으로 읽은 사례는 0/9였다. 양성·음성으로 판단한 발화만 집계하면 Opus의 분모는 3개, GPT의 분모는 8개다. 판독 가능 분모의 차이 5개는 확신 부족 2개와 명료화 요청 3개에서 나왔다. 두 모델의 내용 빈곤 네 상태가 일치한 사례는 4/9다.

오븐을 특정해 달라는 답에서 GPT는 상대에게 필요한 정보를 분명하게 요청했다는 점을 음성의 근거로 삼았다. Opus는 화자가 질문에 관해 답변을 이어 가기 전이므로 말이 공허하고 반복적인지 볼 기회가 부족하다고 설명했다. GPT는 “Hard to say.”에서는 지속한 발화가 부족해 판단을 유보했다. 이 결과만으로 문구 자체가 차이의 원인이라고 단정할 수 없다. 세 확신 부족 표현은 서로 다른 질문과 짝지었다.

DAIS-C 분석에 가져갈 판단은 같은 응답에서 **반응 유형은 읽을 수 있어도 임상 항목의 판독 가능성은 별개**라는 점이다. 기존 계획대로 두 판독자의 상태별 n/전체 N과 판독 가능 분모를 각각 표시한다. 이번 예제에는 실제 환자 발화, 내용 빈곤 양성 사례 또는 전문의 정답이 없다. 이 결과로 어느 판독자의 임상 정확도가 높은지 추정할 수 없다. [앞선 점검의 양성 예제 및 결과](../boundary-calibration-20261121/RESULTS.ko.md)

## 실행 및 검산

예제·기대 판정·기존 지시의 해시를 호출 전에 고정했다. 각 판독자는 사례 하나와 양식 하나만 보고 매번 새 세션에서 응답했다. 36개 세션의 입력 해시와 출력 원문, 근거 구절을 검산했다. 형식 오류 0건, 도구 호출 0건이었다. Opus 원응답 10개는 JSON을 감싼 Markdown 코드 펜스만 제거해 읽었다. GPT는 CLI 표시 모델이 `gpt-6.1-sol`이었고 독립적인 서버 스냅샷 ID는 제공되지 않았다. Opus는 응답 메타데이터에서 `claude-opus-5-5`를 확인했다. 환자 전사 열람·전송과 발화기 실행은 0건이다.
