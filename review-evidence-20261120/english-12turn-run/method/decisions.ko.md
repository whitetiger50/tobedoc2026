# 영어 12턴 면담 탐색 비교의 사전 결정

2026년 11월 21일 KST. 팀이 PatientHub의 PSYCHE식 영어 페르소나를 B로 확정했다. 기존 계획의 GPT·Opus 각 2회 경로를 선택한다. 일차 비교는 T1–B, 수정 기여도는 T1–T0다. 4개의 개발 사례 및 별도로 작성한 8개의 보류 사례를 사용한다. 결과를 보기 전에 확정한 기준은 아래와 같다.

1. 각 사례의 같은 회차·같은 판독자 점수를 짝짓는다. 두 회차 방향이 같아야 승·동·패로 센다. 방향이 달라지면 불안정, 결측이면 미완료로 기록한다. 분모는 언제나 보류 사례 8개다. 두 판독자 모두 해당 대비에서 5/8 이상 승리해야 일관된 개선 신호를 보고할 수 있다. 개발 대조는 사례 수에 합산하지 않는다. GPT 생성기와 GPT 판독기의 모델 계열이 같으므로 두 판독 결과를 각각 제시한다.
2. 각 판독자의 보류 자연 면담 전체 48평점에서 한 범주가 80% 이상이면 포화로 표시하고 우위 판정을 유보한다. 조건별·회차별 분포도 함께 공개한다. 결측이 있을 때는 완료 수와 예정 수를 함께 표시한다. 개발 오류 대조 4쌍 중 어떤 쌍도 양회에 걸쳐 오류본이 원본보다 낮지 않으면 그 판독자의 구분력을 유보한다. 독립 검토에서 대화 기능을 보존했다고 판단한 길이 대조에서 반복되는 점수 이동도 별도로 표시한다. 길이만 바꾼 2개 이상의 서로 다른 사례에서 양회에 걸쳐 같은 길이 편향(장문 선호 또는 단문 선호)이 나타나면 우위를 유보한다.
3. 사례 작성자는 발화기·기존 환자·가설 결과를 받지 않는다. 평정에는 중립적인 사례와 실제 12문답을 제시한다. 조건·개발/보류 표식·사례 번호·회차·대조 종류는 모델에 전달하지 않는다. 같은 사례에서 모든 조건은 모든 질문을 같은 순서로 받지만 질문자는 답에 적응하지 않는다. 사례별로 모호 질문, 그다음 재진술, 명료 질문, 명시적 예시 요청 기회를 미리 표기한다. 통계 단위는 사례다.
4. 전체 현실성 판독과 별도로 출처를 가린 보조 판독에서 모호 질문에 대한 확인 후 차례 양보, 먼저 일화를 말하고 나중에 확인, 명료 질문에서 불필요한 확인, 요청 때 실제 사례 제시, 중요한 설정과의 명백한 모순, 고정된 다음 질문이 앞선 확인 요청을 해결하지 못한 경우를 기록한다. 마지막 경우는 고정 면담의 한계로 다룬다. 불필요한 확인 또는 사실 모순이 상대 조건보다 늘어난 사례가 같은 항목에서 2개 이상이면 해당 대비의 우위 판정을 유보한다. 불분명하면 별도 유보로 코딩한다. 개선을 관찰할 기회가 없는 경우를 실패로 세지 않는다.
5. 개발 오류는 D01을 임상 보고서식 말투, D02를 문맥에 무관하게 돌아오는 동일 문장, D03을 12개 답의 고정 자리 이동, D04를 환자가 면담자 역할로 이탈하는 변형으로 정한다. D01·D03은 단축, D02·D04는 확장한다. 원본 사실·정서·질문에 대한 대화 행동을 유지하며 환자 발화 전체 단어 수 기준 20–50%를 목표로 한다. 중립성은 원점수 공개 전 별개로 검토한다. 핵심 사실·확신·감정·의도·차례 기능이 달라지면 그 쌍의 길이 효과를 유보한다. 점수 차이를 보고 다시 작성하지 않는다.
6. 서식은 공통 질문/답 필드로 통일하고 환자가 실제로 출력한 말버릇·서식·역할 이탈은 보존한다. Opus 설계 검토가 제안한 조건 맞히기는 개발 단계의 자연 원문 네 개가 모두 T0이므로 적용할 수 없다. 원래 계획에 없던 오류 3/4 규칙도 적용하지 않는다. 마스킹은 출처 정보만 가리므로 말투로 출처를 추측했을 가능성은 남는다.
7. 결과 없는 기술 실패는 로그·기존 세션을 확인해 안전하게 복구한다. 표현이나 결과 때문에 다시 생성하거나 다시 판독하지 않는다. 최초 출력이 존재하면 보존한다. 전송 성공 여부를 해소할 수 없으면 결측 처리한다. 구독 사용만 허용하며 Codex 주간 계정 사용률 44%에서 시작해 신규 호출은 52%에서 중단한다. 우선순위는 진짜 최초 기록, 공정한 짝 비교, 실제 완료 분모다.
