## 3. 무엇을 고치고 어떻게 시험할 것인가

DAIS-C Q2에서 환자는 7명 중 5명이 되물었다. 개발판의 21개 중 **되묻기가 들어간 답**은 7개였지만, **첫 반응 자체가 명료화 요청**인 답은 1개였다. 나머지 6개는 사례를 설명한 뒤에 질문을 되돌렸다. 전개로 분류된 답 20개 모두에서 카드의 일화가 쓰였다. 개선 가설은 ‘관련 경험이 떠오름’과 ‘질문의 의미를 충분히 이해함’을 구분하면 대화 차례가 자연스러워진다는 것이다. 5/7을 생성 목표로 주지 않는다. [실제 문답과 입력의 대조](../dais-generator-20261121/Q2-ERROR-ANALYSIS.ko.md)

- **수정은 한 가지다.** T1은 범위가 불분명하면 확인하고 차례를 넘길 수 있고, 분명하면 짧게 답하거나 필요한 설명을 할 수 있다고 지시한다. T0/T1에 같은 카드를 써 이 한 문단의 기여를 본다. 별도로 설계한 카드 수정은 후속 가설로 보관한다. 세 조건 모두에 사용하는 새 카드에는 성격·병식·지식·당사자가 경험한 사실을 적고, 각 질문에 쓸 모범 일화·목표 반응·정답 문장은 넣지 않는다.
- **공정한 입력을 만든다.** 사례 원장 하나에서 B용 MFC(배경·병력·행동)와 T용 사실·의사소통 자료를 만든다. 어느 한쪽에만 중요한 사실·증상·공개 태도가 들어가는지 필드별로 대조한다. 원장에 없는 정보는 양쪽 모두 미설정으로 처리한다. B는 원래의 메시지 이력, T는 기존 JSON 이력을 쓰되 각 조건이 실제로 주고받은 모든 대화를 시간순으로 보존한다. 공통 질문·생성 모델(GPT-6.1 Sol, medium 제안)·출력 언어·도구·재시도 정책을 고정한다. B 대 T는 두 실제 구현의 비교이고, T1 대 T0가 한 문단의 효과를 분리한다. 기존 T 입력 빌더의 개발용 전용 검사를 우회하지 않고, 보류 사례를 다루는 별도 입출력 경로를 검증한다.
- **새 영어 사례 8개를 보류한다.** 조직적인 대화와 환청·망상 내용이 공존하는 사례, 사고 조직 변화가 설정된 사례, 자발 발화가 적은 사례, 치료 중 안정된 사례 각 2개다. 이 배분은 임상 유병률의 추정치가 아니다. 별도 개발 사례 4개에서만 입력 및 판독 통제를 준비한다. 보류용 카드·질문은 T1 수정자에게 노출하지 않고 내용 동등성 담당자가 동결한다.
- **면담당 의사 질문 12개와 환자 답 12개다.** 도입·현재 걱정(1–2), 경험의 구체화·시점(3–4), 생활 기능·일과(5–6), 경험의 의미·의도 확인(7–8), 대인관계·대처(9–10), 치료에 대한 생각·마무리(11–12)를 기본 틀로 쓴다. 사례별 문구는 세 조건에 같다. 모호할 여지가 있는 표현은 일부에만 두고, 바로 다음 질문에서 모든 조건에 같은 중립적 재진술을 제공한다. 예를 들면 “How have things been going lately?” 뒤에 “I mean your usual activities at home. How did yesterday go?”처럼 범위를 좁힌다. 앞선 답에 없던 말을 환자가 했다고 전제하지 않는다. 이 문구는 설계 설명용이며 보류 면담에 그대로 넣지 않는다. 명백히 사실을 물은 턴과 예를 명시적으로 요청한 턴도 둔다. 정해진 질문이 바로 전 답과 안 맞았는지 별도로 남긴다.
- **근거는 전체 면담 판독 뒤에 읽는다.** 사례 프로필과 면담 전체만 제시하고 조건·생성 프롬프트·목표 행동·다른 점수는 가린다. 세 조건의 전사를 같은 형식으로 제시하며 길이, 문체, 실제 머뭇거림이나 역할 이탈을 편집하지 않는다. 원문 인용과 턴 번호를 받는다. 조건 키를 열기 전 별도 검토에서 ‘사례를 먼저 설명하고 뒤늦게 확인’, ‘명료한 질문에도 불필요하게 되물음’, ‘요청한 예에 응답’, ‘중요 사실과 모순’을 **기회가 있었던 턴**을 분모로 기록한다. 이 보조 관찰은 총점을 대체하거나 임상 소견으로 환산하지 않는다.

## 4. 금요일용 비교와 정식 채택의 경계

| 보류 사례 8개 | 각 사례에서 B/T0/T1을 한 번씩 생성한다. 자연 면담 24개·환자 답 288턴이다. 개발 자료까지 합쳐 자연 면담 28개·생성 336턴·서로 다른 판독 입력 36개다. 통제 변형 제작·검수 시간은 별도다. |
| 우선 판독 경로 | 팀의 GPT-6.1 Sol·Opus 5.5·Gemini 4 Argon을 모두 같은 원칙으로 쓸 수 있고 시간·한도가 맞으면 36×3×5 = **540회**. 모델별 5회 중앙값과 세 중앙값의 중앙값을 각각 보고한다. 작은 통제 표본 때문에 여전히 탐색 비교다. |
| 현실적인 축소 경로 | Gemini 이용 경로 또는 5회 판독 예산이 월요일까지 확보되지 않으면, 이미 사용한 GPT·Opus로 36×2×2 = **144회**. 두 판독자의 회차별 점수를 그대로 보고하고 두 모델의 통합 현실성 점수를 만들지 않는다. 로컬에 Gemini CLI가 없다는 사실만 확인됐으며 웹·계정 사용 가능성은 미확인이다. |

두 경로 모두 생성 GPT와 판독 GPT는 같은 계열이므로 다른 계열 판독자의 결과를 따로 보여준다. 팀안에 따라 판독용 GPT는 high, Opus는 medium을 우선하고 Gemini의 실제 설정과 모델 ID는 접근 확인 뒤 기록한다. 지원하지 않는 설정을 임의로 동일하다고 간주하지 않는다. 오류 변형에 모델별 대표점수가 원본보다 한 쌍도 낮아지지 않거나, 어느 자연 점수 범주 하나에 거의 모두 몰리면 해당 모델 점수의 구분력을 유보한다. 개발 단계의 통제는 오작동을 발견하는 용도이고 네 쌍으로 정식 민감도를 인증하지 않는다.

**판정 규칙을 미리 정한다.** 1차 대비는 T1 대 B, 수정 효과 대비는 T1 대 T0다. B 대 T0는 원래 격차를 설명한다. 사례별로 점수 1–4의 승·동률·패를 판독자별로 표시한다. 5회 경로는 모델별 중앙값, 2회 경로는 양회 비교 방향이 일치할 때만 승·패·동률로 분류하고 나머지는 ‘회차 불안정’으로 남긴다. 비교는 미리 짝지은 같은 회차끼리 한다. 12개 턴·반복 판독·세 모델을 독립 사례 수로 더하지 않는다.

금요일 보고에서 ‘일관된 개선 **신호**’라고 쓸 제안 기준은 **모든 참여 판독자에서 8사례 중 적어도 5사례가 같은 대비에서 승리**하고, 진단 가능한 사실 모순이나 명료한 질문에서의 불필요한 되묻기 증가가 반복되는 양상이 없는 경우다. 이는 팀의 정식 채택 문턱과 다른 실무적 요약 기준이다. 탈락·결측·유보를 빼서 승리 분모를 줄이지 않는다. T1이 B만 앞서면 원본 대비 수정 기여는 유보한다. T1이 T0만 앞서면 B 대비 경쟁력은 유보한다. 동점·모델 간 반대 결과·자연 면담에서 특정 점수에 80% 이상 집중·길이 변화에 따른 순위 이동은 함께 제시하고 포화 또는 불안정하면 현실성 우위 판단을 유보한다. 사실·질문 대응이 악화되면 점수와 악화 양상을 병기한다. 사례 8개·조건별 생성 1회이므로 생성 변동과 확증적 효과량은 남는다.

**정식 평가자 채택은 별도다.** 팀안은 자연 24대화와 오류·길이 변형 각 12개, 세 모델×5회로 총 720판독이다. 유효 원평점 ≥99%, 자연 면담 15평점 완전 ≥23/24, 모델별 반복 순서형 α≥.80(군집 95% CI 하한 ≥.67), 일치율 ≥80%, 모델간 α≥.67(CI 하한 ≥.50), 오류·길이 각각 10/12 등의 원 문턱과 모든 부대 조건을 그대로 적용한다. 중립 변형·반복·점수 분포까지 확인하고 조건부 채택된 패널만 후속 미사용 사례의 주결과에 쓴다. 한국어에서 영어로 바뀌었으므로 영어용 적용 범위를 명시한다. **540회나 144회를 원래 720회에서 차감해 채택을 선언하지 않는다.** 이후 독립 임상 판독은 같은 프로필·면담·앵커에서 별도로 시행한다.
